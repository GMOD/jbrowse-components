# ADR-201: A cells step bins as it walks

## Status

Accepted (2026-09-30). The lever
[ADR-197](adr-197-a-bin-cuts-an-interval-at-its-edges.md) left and
[ADR-199](adr-199-the-maf-display-stays-its-own-and-shares-the-grammars-kernels.md)
named as the one identity walk.

## Context

The declared MAF identity is `cells`, an interval `bin` over the runs' extents
and an `aggregate` mean of `match` weighted by `overlap`. ADR-197 fused the bin
and the aggregate, but `cells` still wrote every run into a table first, and
that walk was most of the gap to the MAF display's `buildIdentityRuns`, which
counts matches in the one pass over the text. A display also writes the three
steps into different lists: `marks_maf_identity` puts `cells` in the display's
transform and the bin and aggregate in the span's, so a fusion within one step
list never meets them together.

## Decision

- **`binnedCellMatches` walks the rows' bytes once** (`cellMatches.ts`),
  counting each bin's bases matched and compared as it passes them, and
  meeting each run with the bins the bin step would cut it into, in the order
  the `cells` lanes would hold it, an insertion ahead of the run still open.
  The groups therefore come out where the three steps put them, with their
  ids, hover JSON and section order, and a sum of 0s and 1s weighted by
  whole-base overlaps is an integer, so every mean is theirs to the bit.
- **`fusesCellMatches` is the predicate**: the bin cuts `start` and `end` at an
  integer step and writes them as `start` and `end`, the aggregate groups by
  those, and every op is `sum` or `mean` of `match` weighted by `overlap`.
  Anything else runs the steps as written. A row whose start is not a whole
  base inside a Uint32, or a section whose bins spread too thinly for a dense
  index, runs them as written too.
- **A trailing `cells` moves into the layers that fuse it.** `runLayers` runs
  the shared or facet steps up to a final `cells`, then hands that `cells` to
  each layer whose own steps open with the fusing bin and aggregate, and runs
  it once for the rest. A facet's section field reaches the walk's rows as it
  reaches an aggregate's (`keepingSection`).
- **Off the plugin ABI**, as ADR-197's kernel is: `cellsStep.ts` holds the
  `cells` step and the byte helpers both walks read, and `featureTransforms.ts`
  imports both files by relative path.

## Consequences

- ADR-197's consequence that a kernel fuses only within one step list holds
  for the bin and aggregate; a trailing `cells` is the one step that crosses
  into a layer's list.
- `cellMatches.test.ts` holds the walk equal to the three steps over random
  blocks, under a facet and without, with insertions, gaps and mismatches, and
  spies that `runSteps` takes it.
