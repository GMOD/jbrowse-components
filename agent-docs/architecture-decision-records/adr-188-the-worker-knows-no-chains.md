# ADR-188: The worker knows no chains

## Status

Accepted (2026-09-28).

## Context

The worker built chains only when `linkedReads` was on, so the setting was an
`rpcProps` key and toggling "View as pairs" refetched every region. One worker
call sees one region, and a chain crossing a region boundary is the case chain
mode exists for, so the main thread re-joined chains by name anyway:
`reconcileChainSuppAcrossRegions` for the supplementary marker, a second join
for the hover's read ids, and the layout's `mergeChains`.

## Decision

- **The worker knows no chains.** `attachChainFields` numbers each region's
  chains on the main thread, memoized on `readKeys`, and settles every
  per-chain answer from the union across regions and lanes: the supplementary
  marker, the per-mate split bits, and a supplementary's pair orientation,
  which it takes from its primary in chain mode alone. The display's
  `chainAttachment` / `chainedByGroup` feed the layout; `rawDataByGroup`
  stays chain-free, and pileup mode never calls it.
- **What chain mode still changes about a fetch is the unit a facet keeps
  whole.** The RPC's facet is `{ field, unit?: 'read' | 'chain' }`, and
  `unit: 'chain'` is sent only when chain mode is on and a facet is in effect,
  so the toggle over ungrouped data leaves `rpcProps` equal.
- **Chain mode sends no sort tag and no soft clipping**, since chain layout
  reads neither.

## Cost

The numbering moved from the worker to the main thread, and that is the trade
this records. Replaying a view's regions landing one at a time, main-thread
time summed over the landings:

A view of one or two regions pays the numbering the worker used to, once per
fetched region and in proportion to its reads; the memo makes a pan within
fetched data free. A view of many regions pays less than before, because the
union re-answers only the chains two regions share, where the reconcile
re-answered every read. Pileup mode pays nothing. Colin accepted the few-region
cost as a one-time cost per fetch, against a refetch of every region at each
toggle, which was not measured.

Two ways to keep the numbering in the worker were not taken. Numbering in
every fetch would charge pileup users for a mode they never turn on; numbering
in chain mode alone is the refetching design this replaces. Hashing names
straight out of the name block, instead of slicing a string per read into a
`Map`, is the unmeasured way to make the main-thread numbering cheaper: the
profile of the one-region case is mostly those strings and the collection
after them.

## The vocabulary

The spelling is grammar-of-graphics vocabulary and costs nothing at runtime:
`unit` is one field on an RPC argument.

| grammar term | here | spelled |
| --- | --- | --- |
| observation unit | a read, or a chain (mates and split segments, one QNAME) | `facet.unit`; the `linkedReads` slot; `isChainMode` |
| facet | the field the sections stack by, and its domain | `facet` slot, RPC `facet`, `Facet` type |
| colour channel | the read fill | `color` slot, resolved as `colorBy` |

**`unit`, not `group`.** ggplot2's `group` aesthetic and Vega-Lite's `detail`
channel join observations into one line, which is the connecting line's role
here. A chain is more than that: the layout packs it (a row is a chain), the
hit test boxes it, and the split-read colour describes it, which is tidy
data's observational unit with reads nested in it. Neither grammar has a flag
keeping a group whole across facets; each would facet on a group-level
variable computed first, which is what the chain's representative read and a
dimension's `chainKey` are. `group` would also bring back the "Group by"
collision the facet rename removed.

## Consequences

- The seven chain fields left `WorkerPileupData` for `ChainFields`
  (`ChainedPileupData` is the layout's input). A consumer reading them off
  `rpcDataMap` reads them off `chainedByGroup` instead.
- The unit still has two other spellings, the `linkedReads` slot and
  `isChainMode`:
  [ideas/waiting-on-a-call/linked-reads-slot-is-the-unit.md](../ideas/waiting-on-a-call/linked-reads-slot-is-the-unit.md).
