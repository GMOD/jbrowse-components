# ADR-091: A display's settings are not a declaration

## Status

Rejected (2026-08-24). The work is on the unlanded branch
`worktree-manhattan-lazy-spike` (29 commits), which stays as the record and
does not land. What was salvaged onto main is listed under Consequences.
Written against
[ideas/a-display-declares-itself](../ideas/a-display-declares-itself.md),
whose Result section carries the measurements this rests on.

## Context

[ADR-089](adr-089-a-track-type-is-a-spec-the-factory-composes-the-stack.md)
made a track type a spec and was explicit that the in-tree stack is unchanged.
The idea doc asked the question ADR-089 deliberately did not: is the factory
also where in-tree displays should live, and can a display's settings be one
declared table that the schema, the fetch key and the render state derive from?
Level 0 tested it by porting `LinearManhattanDisplay`, the smallest display with
a real scale, hit test, legend, tooltip, hand-written shader and `renderSvg`,
against a budget committed before the port.

The port fit: all 25 gwas suites passed with import changes only, and the
config docs page regenerated byte-identical. It was then measured:

- **Every field the port added to `defineDisplay` was an override hook.** Six
  fields, each with exactly one consumer, each of the shape *let me override a
  piece of what you compose*: `rpc.inputs`, `renderState`, `extend`, `index`,
  `component`, `svgBody`. The domain half of the display (the LD model, the
  index SNP, both menus, ~478 lines against a 320-line budget) sat inside an
  imperative `extend`, and the RPC serialization (two `renameRegions` passes
  over adapters that disagree on contig spelling) could not be expressed at
  all. The pre-port commitment named this outcome as the falsifier: "if holding
  Manhattan requires a spec field per mixin hook, the imperative altitude is the
  real contract".
- **A state model is eager**, so everything a spec names by value loads at
  plugin install: 40 modules and ~240 KB onto the gwas plugin's startup path,
  including the HAL, both renderer bases, `DisplayChrome` and the `bar` shader
  for a display that draws points.
- **Four generated censuses lost the display**, two silently, because they key
  on `new DisplayType(`.
- **Lines were a wash**: the display went 1,278 to 1,052 and the factory 431 to
  658.

The port was reverted on the branch and the reusable half moved below the
factory as a data-only settings table (`params.ts`: slot definition plus an
`affects: 'fetch' | 'encode' | 'frame'` tag). That was measured too:

- **0 getters eliminated.** Both converted displays kept one hand-written getter
  per param; only the right-hand side changed. Deleting them moves the break to
  the display model's public surface, which menus, dialogs, renderers, SVG
  export and third-party plugins all read. The measured target was 60
  declarable getters out of 321, and the number removed was 0.
- **`affects` derives a correct fetch payload on 1 of 6 displays.** The values
  that invalidate a fetch are usually derived (a precedence ladder, a resolution
  against fetched metadata, an ordering) and raw-slot transport is the special
  case. The encode equivalent found 0 consumers in 2 displays and was deleted.
  What was left of the tag was a claim a hand-written per-display test holds the
  display to, and one such test existed.
- **The table cannot hold meaning.** The deciding guard was alignments'
  `colorBy`: the table holds it as one `maybeFrozen` promotable slot and says
  nothing about the six-variant union with a nested six-field `modifications`
  object inside it. The larger ambition of deriving menu rows and legends from
  the table was not supported.
- **A shared setting acquires two owners.** The table owns the slot; a
  cross-cutting mixin (`LegendMixin`, `RowHeightMixin`,
  `WiggleScoreConfigMixin`) owns the accessor, the setter, the pin and the menu
  row, reading the slot through a host cast. The tree's six such mixins already
  bundle slot, getter, setter, pin, menu row and dialog and retire that whole
  set across four to eight displays each, which is the better answer for the
  reducible half.

## Decision

**In-tree displays compose their own MST chain, and their settings live where
they always did: a config schema, and typed getters reading it through
`getConf` / `resolveConf`.** The factory stays what ADR-089 made it, a one-call
door for a third party, and grows a field only on a third party's pull.

The bar this failed is whether the spec expresses a display's concepts natively
or holds them through escape hatches. It held them. A declaration that needs a
function-valued option per display concept has stopped being a declaration, and
the branch's own don't-redo list (a `transport:` field, a fourth `affects`
value, a `normalize:` hook) is the list of holes the next display would have
needed.

## Consequences

Salvaged onto main, each independent of the declaration:

- **Four config-read defects the branch's checks found**, verified there by
  sabotage. `symlogConstant` was read by `WiggleScoreConfigMixin` against hosts
  whose schema never declared it; it now lives on `WiggleCommonMixin`, whose
  hosts do. `RegionTooLargeMixin` read `fetchSizeLimit` and `forceLoad` off
  `baseLinearDisplayConfigSchema` while five composers did not extend it; the
  pair is now the mixin's own field table
  (`regionTooLargeConfigSchemaFields`), spread by the base schema and by those
  five, on the `RowHeightMixin` + `rowHeightConfigSchemaFields` precedent. This
  advertises two `advanced` slots on `LinearWiggleDisplay`,
  `MultiLinearWiggleDisplay` and `LinearReferenceSequenceDisplay` that do
  nothing while those displays leave the byte gate off; that is the cost of a
  mixin owning its slots, and an `undefined` budget is a gate that never fires
  the moment one turns it on. `BaseTrackModel.textSearchAdapter` read a
  top-level slot that lives at `textSearching.textSearchAdapter` and answered
  `undefined` for every track ever configured with one; `refNameMismatch` read a
  raw `assemblyNames` slot that `ReferenceSequenceTrack`'s schema omits and was
  inert for that track type. And a worker payload could be built from an
  unresolved config snapshot; `ResolvedConfigSnapshot` is a brand the resolving
  reader applies and the payload builder requires.
- **`defineDisplay` reads a `promotedBase` param through `resolveConf`.** The
  factory read every param with `getConf`, so a third-party spec declaring a
  promotable slot got the inherit sentinel back as `undefined`, and its
  `ParamValues` were typed off `defaultValue`, which a promotable slot does not
  have. The branch fixed this with a declared `read: 'resolved'` axis the author
  had to restate; main derives it from the slot definition, which already says
  it is promotable, and types the value with core's own
  `SlotValueResolvedFromDef`. No new declaration axis, and the wrong verb cannot
  be written.
- **The eager-load finding stands as a constraint on the third-party factory**:
  everything a spec names by value loads with the state model. A spec display's
  drawing should be able to load late, which is a change to `defineDisplay`'s
  public shape and is not made here.

Not salvaged, and why:

- **The composition-walk checks** (`compositionChains.ts` and the three tests
  over it, ~2,500 lines in `products/jbrowse-web/src/tests/`). They found the
  four defects above, and they are a source-parsing walk of every display's
  mixin chain standing in for what tsc already does for 18 of 19 promotable
  slots through `ConfigurationSlotValue` and for every host cast through
  `HostChecksSlotNames`. The population they reach that tsc does not is the
  bare `getConf(self, 'x')` on a widened holder, and
  `scripts/configReadTypeGaps.txt` is the committed list of those, whose header
  has always asked for the parameter to be narrowed rather than for a second
  checker. The branch's own handoff measured that 103 of its 125 remaining
  entries sit outside any composition chain.
- **`params.ts`, `paramReader.ts` and the converted Manhattan and HiC
  declarations.** The table above.

## Rejected alternatives

The branch tried and measured each of these before this ADR rejected the whole:

- **Resolving the declaration into a bag on the model** (`declaredParams`).
  Reading settings through a loop erases the types the config readers derive,
  and four pieces of machinery grew to buy them back. Reverted on the branch.
- **A `transport:` field, a fourth `affects` value, a `normalize:` hook.** Each
  is the escape hatch a declaration grows when it meets the next display.
- **A tree-wide check that promotable slots are read with `resolveConf`.**
  Redundant with the compile-time guard for all but three shapes.

## What would reopen this

A third-party author, not an in-tree display, pulling on the factory for a
concept the spec cannot hold. ADR-089's rule is unchanged: a field joins on a
consumer's pull, and that consumer is outside the repo.
