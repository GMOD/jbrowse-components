# ADR-190: The MAF display stays off the mark display's `Feature` steps

## Status

Rejected (2026-09-28). Measured by `plugins/maf/benches/mafOnMarks.bench.ts`
after the first four items of [maf-onto-marks](../handoffs/maf-onto-marks.md)
landed, none of which had been timed against the display it would replace.

## Context

ADR-186, ADR-187 and ADR-189 put a MAF's species rows on the mark display:
`flatten` fans each block's `alignments` out into a row per species, `cells`
turns each row into runs against the block's reference, and the adapter lists
the rows in the guide tree's order. The handoff's remaining items (a band
stack, a coarse tier, the frames join, the glyphs) would each add a layer to
that path, and rule 3 of
[GRAMMAR_OF_GRAPHICS.md](../reference/GRAMMAR_OF_GRAPHICS.md) §"Four rules"
lands a declared form only at the hand-written path's speed or better.

The bench fetches one region of the synthetic MAF-tabix fixture once, since
`MafFeature` holds its parse eagerly, and times what each path does with the
same features: the MAF display's pack, placement and `buildMafChannels`, and
the `marks_maf_cells` declaration as `CoreGetEncodedLayers` runs it. Two
shapes are 26 species at the wide blocks
[MAF_WORKER_PIPELINE.md](../reference/MAF_WORKER_PIPELINE.md) profiles and at
the narrow blocks real files have; the third is 470 species, the hg38 track the
mark display's MAF example reads, over 200 kb. The MAF arms leave out the
worker's coverage and encode every base where the display samples one per
window below half a pixel, both in the Feature steps' favour.

The identity a config can declare today, `bin` and `aggregate mean` over
`match` behind `cells`, is also the wrong one. `bin` places a run by its
start, so a 500-base match run counts once, in one bin, and a bin it crosses
sees only the runs starting in it. Against bases matched over bases compared,
counted straight off the text, it is off by up to
0.984<!--m:maf-on-marks-identity.featuresWorst.max-->.

## Decision

- **The MAF display keeps its own path** for its rows, identity plot, band and
  overlays. It already draws every GPU layer through render-core's span, bar
  and coverage marks, which is rule 4's convergence: the grammar supplies the
  parts, the track stays its format.
- **What landed stays.** `flatten` over a record, the `cells` step, the
  adapter's row listing and the mark display's pinned, scrolling rows serve
  the mark display over any source, and a MAF on the mark display stays a
  declared view for a plot the MAF display does not draw, at the cost above.
- **The handoff's items 5 to 11 do not go onto the `Feature` steps.**

## Consequences

The bench's lane arms are a spike, `packages/core/benches/columnSteps.ts`,
running the same declaration with each step that makes rows writing typed
lanes and the facet ordering the species rows ahead of `cells`. It answers the
Feature steps run for run, and its row lookup answers what the hit index does
at random hovers. It lands at
0.76-1.04x<!--m:maf-on-marks-cells.rowMajorVsMaf.range--> the MAF display's time, and
its identity, which cuts each run at the bin edges and weights the mean by
bases, is exact at
0.81-2.00x<!--m:maf-on-marks-identity.columnsIdentityVsMaf.range-->.
[ADR-191](adr-191-the-mark-pipeline-runs-over-tables.md) to
[ADR-193](adr-193-an-adapter-answers-the-mark-pipeline-its-typed-arrays.md)
built it, and [maf-onto-marks](../handoffs/maf-onto-marks.md) holds what the
spike left open.

## Revisit if

The mark display's steps that make rows write typed lanes. The port then
resumes against this bench, whose lane arms become the production path's.
