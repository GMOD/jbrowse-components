## Findings

- **The grammar docs go stale the moment stage 2 lands.**
  `reference/GRAMMAR_OF_GRAPHICS.md` §"What the tree does that the grammars do
  not", the row-axis bullet, still says the mark display's rows re-pack their
  lanes through `facetRegion` because bar and point spend their one sampler on
  the ramp. After landing it reads: the mark display's `rows` ride the table
  too, keyed at arrival; only a `facet` still offsets its rows, since its
  sections are of variable height.
- **Dead optionality in the value scale.** `valueScaleSchema`'s `autoscale`
  option is passed by every caller (alignments coverage, the mark display,
  wiggle; Manhattan takes the mark display's), so `ValueScaleOptions.autoscale?`,
  `ScoreScaleMixin.autoscaleType: string | undefined`, the
  `self.autoscaleType !== undefined` guard in `wiggle-core/scoreMenuItems.ts`
  and the four `string | undefined` parameters in `wiggle-core/autoscale.ts`
  carry a case no display is. Make `autoscale` required and the type `string`.
- **Named plot presets need no new mechanism.** Colin's steer from the morning
  round was "people should not need a plugin for custom plots". Reading the
  code: `markListSchema(defaults)` (ADR-178) already is a named plot preset,
  spelled as a display type with a default `marks`, and a user needs no plugin
  at all to author a plot, only a copyable config. What still needs a plugin is
  a data-side join the adapter runs (Manhattan's LD), which is not a grammar
  piece. The examples page below is the copyable-preset surface. No registry,
  no `plot` slot: a second spelling of `marks`.
- **Not defects, checked:** `makeCellLeftMapper` (named "no production
  caller" in memory) is the test oracle for `bpAtPx` and the 1-bp pivot rule
  in five suites, keep it; the CLI validator's copies of the mark vocabulary,
  specs and rules are generated by `scripts/generateMarkRules.ts`, not
  hand-kept; "Color by LD" over a bar-only plot now replaces the whole
  `marks` list (`setLdColoring`), so the stage-2 handoff's item is closed; an
  LD mark behind a `bin`+`aggregate` adopting an index nothing joins is
  reachable by no shipped config and stays as it is.
- **Demonstrations.** Only `alu_age` and `read_marks` teach the mark display,
  and the parked idea
  [mark-display-showcase-pages](../ideas/collections/mark-display-showcase-pages.md)
  ranks an examples gallery first. Drafted beside this file:
  `grammar-review-2026-09-26/mark_display_examples.page.txt` (→
  `website/docs/config_guides/mark_display_examples.md`) and
  `grammar-review-2026-09-26/mark_display_examples.spec.txt` (→
  `website/scripts/specs/mark_display_examples.ts`, export
  `markDisplayExampleSpecs`, spread into `website/scripts/screenshot-specs.ts`).
  Twelve sections, one complete `addtrack` config each with a `config=` live
  link and a figure: bars, points with a shape scale, a viridis ramp, a
  threshold, a histogram, a mean per bin, a pileup, a facet, labels, rules
  and a title, all over the hosted Alu BED (`gene_density` config, 30 kb or

### Alignments colour override (Opus build agent, 2026-09-26)

Built and committed as `9f9914931a` on `worktree-agent-a4108f312c7d1b76b`
("A declared colour range paints on every alignments read field"); stopped
before the docs, the rebase and `pnpm verify`. Gates run in its worktree:
`pnpm typecheck` green; `npx jest plugins/alignments` 217 suites / 2531 tests
green, including the new
`LinearAlignmentsDisplay/declaredCategoryColors.test.ts` (RR paints
`#d95f02` and LR keeps its default on the uniform slots, the swatch and the
Canvas2D fill, the key shows both; each of the five formerly collapsed levels
recolours alone; a threshold range over insert size colours its three bins).

What it did: each read field names its levels (`strand` 1/-1;
`pairOrientation` LR/RL/RR/LL and `''` for an unsplit read; insert size
short/normal/long; `mapq` 255; tags and `mateRefName` `''` for no value), and
`range` colours the levels `domain` lists, or the field's own order with no
`domain`; the palette carries a declared colour per read category and one
lookup, `readCategoryColor(palette, category)`, serves the GPU uniforms, the
Canvas2D fill, `categorySwatchColor` and `palettes.ts`; `isBakedScheme` only
marks the per-read main-thread fields now; the SVG export builds its palette
through the model (and so honours `color.value`, which it ignored before).
`categoricalScale` was not used for the fixed-level fields, since it hashes
unlisted values into slots and merges repeated fallback colours.

Zero-image-diff claim: no tracked config declares a range on a preset field,
the category table is empty without one, and the alignments snapshots held;
browser goldens and jbrowse-web suites not run. The one visible change is an
SVG export of a track setting `color.value`, which now matches the screen.
