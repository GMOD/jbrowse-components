# Config spellings

The tables read the display types in `website/static/schema/v5/config.json`,
leaving out what the schema marks deprecated. A display's name drops its
`Display` suffix. The vocabulary the spellings follow is
[ADR-238](../architecture-decision-records/adr-238-every-display-speaks-vega-lite.md);
the work left is [v5-api-convergence](../handoffs/v5-api-convergence.md).

## Where a shared path differs

A path whose members, or enum values, are not the same on every display that
has it. One row per variant.

- A channel below a part's `encoding` compares as the channel's own path, the
  part named after the display: `ribbons.encoding.color.scale` is
  `encoding.color.scale` on ``MultiWaySynteny `ribbons` ``.
- Why is the path's entry in `scripts/configSpellingRulings.ts`, on its first
  row. `open:` marks a difference nothing rules on yet.
- `scripts/configSpellingRulings.test.ts` fails on a differing path with no
  entry, on an entry whose path no longer differs, and on a path that gains or
  loses a variant.
- A slot under a part other than `encoding` meets only its own path, so
  `records.facet`, `records.labels` and `records.tooltip` never meet the
  display's `facet`, `labels` and `tooltip`, `rows.color.scale` never meets
  `encoding.color.scale`, and `labels.subfeatures.placement` never meets
  `labels.lanes.placement`.
- Also outside the table: which string shorthands a slot admits, defaults, and
  the comparative views' `encoding`, which is no display's.
