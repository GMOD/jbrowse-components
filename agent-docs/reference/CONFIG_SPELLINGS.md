# Config spellings

The tables read the display types in `website/static/schema/v5/config.json`,
leaving out what the schema marks deprecated. A display's name drops its
`Display` suffix. The vocabulary the spellings follow is
[ADR-238](../architecture-decision-records/adr-238-every-display-speaks-vega-lite.md);
the work left is [v5-api-convergence](../handoffs/v5-api-convergence.md).

## Where a shared path differs

A path whose members, or enum values, are not the same on every display that
has it. One row per variant.

- A slot compares as its path from the last `encoding` segment with a channel
  below it, else from the last segment that is exactly `facet`, `tooltip`,
  `labels`, `mark` or `placement`. The segments before it name the part, after
  the display: `ribbons.encoding.color.scale` is `encoding.color.scale` on
  ``MultiWaySynteny `ribbons` ``, and `records.facet` is `facet` on
  ``LinearVariant `records` ``.
- `scale`, `legend`, `axis` and `filter` are not on that list: under an
  `encoding` they already compare, and outside one they either do not differ
  or name another thing (`rows.axis` beside the multi-way `axis`).
- Why is the path's entry in `scripts/configSpellingRulings.ts`, on its first
  row.
- `pnpm autogen` refuses to write the table, and
  `scripts/configSpellingRulings.test.ts` fails, on a differing path with no
  entry, on a path that gains or loses a variant, and on an entry whose path
  no longer differs. A display that moves between two existing variants
  changes no count and passes.
- Outside the table: any other word under a part, which meets only its own
  full path (`rows.color.scale` never meets `encoding.color.scale`, and a
  part's own `encoding` never meets the display's); which string shorthands a
  slot admits; defaults; and the comparative views, which are no display's.
  Their `encoding` is the shape the `MultiWaySynteny` `ribbons` rows show.
