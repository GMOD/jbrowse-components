# Synteny: tiers, fetch axes, off-screen mates and picking

## PIF tiers and level of detail

### The two PIF tiers

`jbrowse make-pif` writes two tiers into one tabix-indexed PIF, told apart by a
one-letter seqid prefix: fine (`t`/`q`, per-row CIGAR and every tag, never split;
run `rb break-paf` upstream to split) and coarse (`T`/`Q`, the same row with the
CIGAR folded into a `cr:Z:` coarse CIGAR,
`packages/cigar-utils/src/coarseCigar.ts`, ADR-104). The `#pif` header
(`PifFile.meta`) lets a reader treat a tagless coarse row as one run within the
`--coarse` bound, so `--coarse` must be positive. The renderer walks `cr` where
it would walk `cg` (`CIGAR_RUN`), so a kept gap draws as the same wedge in both
tiers.

### One alignment string per row

A PIF row carries `cg:Z:` and never `cs:Z:`; `make-pif` folds a `cs` into the
CIGAR. `SyntenyFeature.forEachMismatch` prefers `cs` over the CIGAR, so a `cs`
that rode through unflipped beside a flipped `cg` drew every indel on the q
perspective with reversed sense. Don't add a second alignment string without a
reorienter that reverses op order and reverse-complements the spelled-out bases.

### Where `auto` resolves: main thread, once

`resolveLodTier` (`packages/synteny-core/src/lodTier.ts`) is the only place
`auto` becomes a tier. It must run in a display getter that feeds the fetch
cache key, and `BaseOptions.lodMode` is typed `'fine' | 'coarse'` so it cannot
drift back. A decision made adapter-side from `bpPerPx` is invisible to the key:
`bpPerPxBucketKey` is `floor(log2(bpPerPx))`, so zooming across a threshold
inside a bucket changed no key and left coarse ribbons on screen while
`dataCurrent` reported fresh.

Read the threshold with `getCoarseBpPerPxThreshold`, which goes through the slot
path, because `adapterConfig` reads `undefined` for tracks at the default. The
synteny and dotplot surfaces feed the min of both axes: coarse is safe only once
both axes pass the threshold.

### The file has the last word

The slot cannot say whether the file has a coarse tier or the bound it was
folded at. `LodTierInfoMixin` and `installLodTierInfoFetch` read the file's
`PifFile.info()` through `CoreGetInfo` into the volatile `lodTierInfo`, which
`resolveLodTier` reads beside the slot (`effectiveCoarseThreshold`):

- **Info not yet landed:** trust the slot, so landing refetches nothing for a
  default-built file.
- **`hasCoarseTier: false`:** `'fine'` under every mode, pinned `coarse`
  included.
- **Header bound above the slot:** raise the threshold to the bound, since below
  `--coarse` bp/px the fold leans more than a pixel. The clamp goes only up.
- **Headerless two-tier file:** resolve off the slot alone.

`MultiPairwiseSyntenyAdapter` folds its children's headers: one tierless child
pins the whole star to fine. The primary fetch is deliberately not gated on the
info, since gating costs a round trip before every first paint to save one
refetch for a disagreeing file. A failed info read resolves off the slot.

### Identity continuity across the switch

**Nothing user-visible may key off which tier is loaded.** A coarse row is its
fine row with the CIGAR replaced, so `pafIdentity` (`@jbrowse/cigar-utils`) reads
the same bytes on both tiers. `make-pif` must not restate the coarse row's
`de:f:`: a private copy of the chain skipped the `id:f:` rung, and
`blockLen === 0` wrote `de:f:0` (100%) where `pafIdentity` returns 0. Never
recompute divergence from the CIGAR; an M-style `cg` folds mismatches into `M`.

### What the coarse tier solves

The coarse tier cuts per-alignment cost, which suits few huge alignments such as
liftOver chains. It does not reduce alignment count, so for many short alignments
the bottleneck stays N. Read-time binning is declined: reading and parsing N
lines is ~66% of the fetch (construction and everything after is ~34%) and is
upstream of anything an adapter could bin, so binning is capped near 1.5x
(ADR-039). Don't reintroduce runtime collinear chaining (a `maxGap` heuristic,
removed as unreliable and zoom-dependent). Only a precomputed binned tier in
`make-pif` cuts the dominant read cost, and it needs a format change.

### Coarse-by-default and what it costs

Coarse-by-default roughly doubles PIF record count. The tier's value is
`coarse_bytes / fine_bytes`, a function of CIGAR weight per row, and the
crossover is around 30-50 kb blocks. At small blocks `auto` gives up the indel
wedges to read ~11% fewer bytes, a bad trade in fidelity.

## The second synteny fetch, on the target axis

`executeSyntenyFeaturesAndPositions` queries the query axis (the top
`LinearGenomeView` row). With `showOffscreenMates` on, a second query runs on the
target axis and its ribbons flip into the query perspective. The two fetches are
disjoint by where the query end lands, so `f.id()` dedupes within each and no id
crosses between them; `bidirectionalFetch.test.ts`'s no-double-draw case guards
the doubled-alpha artifact. Feature ids are not comparable across a tiered PIF's
two tiers, and both fetches run at one `lodMode`.

### `syntenyId`

`plugins/comparative-adapters/src/util.ts` gives each alignment a
perspective-specific `uniqueId` and a perspective-stable `syntenyId`. PIF v2
carries the input row in a `pi:i:` tag, because PIF writes both perspectives as
separate lines and sorts the file, so `fileOffset` (pre-v2) relates nothing.
All-vs-all PAF numbers its two sides apart on purpose: `markReciprocalDuplicates`
already decided which restatements to collapse, and a join key would fight it.

### Costs of the second fetch

- A whole-genome PAF pays two fetches per level (in-memory adapters share one
  `createSharedSetup` download; an indexed adapter pays a real second query).
  This is why the setting shipped off first.
- Justify changes by completeness of the dropped alignments, not by refNames.
  The refName class has a cheaper fix, and `SyntenyResolveMatchingRegion` needs
  the inverse rename either way.
- How much the query recovers depends on which genome is on top; measure the
  case in hand.

## Off-screen synteny mates, drawn as something other than a ribbon

A synteny band draws a ribbon only when both ends land on a displayed region.
The "Off-screen mates" checkbox (`showOffscreenMates`, on by default) draws the
other alignments as marks in a strip at the band edge, labelled with the contig
they point at. `OffscreenMateOverlay` is a second 2D canvas over the level's,
because the ribbon shader spans the full gap between the axes and a part-height
mark does not fit the instance format. Do not approximate a mark with a
degenerate ribbon: the full-height band reads as an alignment to the locus below.

### Four classes

| class | anchor | mate | why no ribbon | decided | marked on |
| --- | --- | --- | --- | --- | --- |
| **A** | visible query window | no target region reaches it | no second endpoint | worker, per fetch | query axis |
| **B** | no query region reaches it | visible target window | never requested | worker, per fetch | target axis |
| **C** | visible query window | contig the target displays, scrolled off | `overdrawPx` cull | main thread, per repaint | query axis |
| **D** | contig the query displays, scrolled off | visible target window | `overdrawPx` cull | main thread, per repaint | target axis |

- A and B are decided by locus, not contig (`markUnplaced`, `findRegionEntry`).
  Which genome is on top decides how much A is free; never quote one percentage.
  `bidirectionalFetch.test.ts` holds all four classes.
- **C and D cannot be decided in the fetch.** The facing row pans a full
  `syntenyPanBufferPx` without refetching, so a mark decided at fetch time would
  sit beside a ribbon it claims does not exist. `culledRibbonMates` restates the
  `isRibbonCulled` band in the facing axis's cumBp, so a mark and its ribbon
  cannot both draw. It reads the instances, not the feature lanes: `starts`/`ends`
  are untrimmed, and transparent-CIGAR mode has no single instance per block.
- **A row's strip is complete if and only if that row was queried.** B is never
  requested and D only within the pan buffer, so `laneData` enforces the rule in
  the one place draw, hit test, tooltip count and SVG export all read.
- Marks are placed from `views[level]`, the level's upper row; the lower row's
  ruler puts every mark at a wrong offset.
- What a strip draws and names is decided by aligned bp
  ([ADR-138](../architecture-decision-records/adr-138-aligned-bp-ranks-and-gates-the-off-screen-mate-marks.md)).
- Draw and hit test share `offscreenMateStrips`; hover and click share
  `offscreenMateAt`. A mark can stand for a run of anchors, so the click
  navigates to the union of the mate spans under the pointer.
- The strip is one path, not a fill per mark: the mark colour carries alpha, so
  per-mark fills darken with density into a solid ideogram.
- `SVGOffscreenMates` runs the same `drawOffscreenMates` through `PaintLayer`.

### Click destination

`mateNavDestination` resolves the class, coordinate and locstring before the
click takes anything, so an unresolvable mark leaves the viewport capture and
follow anchor untouched. `offscreenMateDestination` is the resolver the tooltip
and click share.

- A click never removes a region and raises a snackbar with an **Undo**
  (`LinearSyntenyOffscreenMateFollow.test.tsx`).
- For a contig the row shows slices of, the click adds a slice in the largest gap
  holding the locus, trimmed so two regions of one contig never overlap
  (`clipLargeBlockToWindow` assumes that). The gap is chosen by the locus, not
  the framed window, because `navSpan` clamps the window to the contig.
- An aliased region is respelled to the canonical refName in place, because
  `navTo` compares `displayedRegions` refNames raw. The scroll class (C, D)
  navigates with the row's spelling off `pxToBp` and canonicalizes both sides of
  its staleness test; `===` silently did nothing for an alias.
- `LinearGenomeView.flyTo` (`flyTo.ts`) plays the scroll class; the show class is
  not flown because `showRegions` changes the row's regions. The arc crosses many
  fetch buckets but costs one extra synteny RPC, because the 500ms leading-edge
  debounce absorbs it. Leave `RHO` and the `fetchInert` seam alone until a
  heavier file says otherwise.

## Synteny picking, measured

`syntenyPickEngine.ts` answers a hover by stabbing a `flatbush` index of
**x-hulls** (one per pickable instance, plus one per tiled feature) and testing
what comes back exactly. The index is 1D (`[minX, 0, maxX, 1]`, since a ribbon
spans the track height), and a hull is `[min, max]` over corners on BOTH axes, so
the index discriminates well when alignments are **collinear** and not at all
when they are not. Fixtures: collinear (two related genomes) and random pairing
(all-vs-all PAF); `kept` counts entries surviving the pickable-width exclusion.
Measure in Chrome via an esbuild bundle, never jest, which inflates this code
6-30x non-uniformly ([BENCHMARKING.md](BENCHMARKING.md)).

At zero skew about half the tree covers any given x, because half the hulls span
the canvas. Each candidate pays `projectCorners` + `isRibbonCulled` at ~80ns, so
12.5ms<!--m:synteny-pick-random.1-10k.warmPickMs--> fills a 16 ms frame and an
all-vs-all hover reads as sluggish. A tighter cap, a bigger `flatbush` node size
or `filterFn` filtering does not help, because the candidates genuinely cover the
stab point; a fix means indexing something other than the hull (per-axis
intervals tested pairwise), which nobody has costed.

### A tiled feature is picked as one body

`cigarMode: 'matches'` (Transparent indels) replaces a feature's full-span
`KIND_BASE` quad with one `KIND_BASE_TILE` per match segment
(`buildSyntenyGeometry.cigarSegmentKind`), so no instance covers a feature, and
the see-through indels between tiles would answer no hover. `buildPickIndex`
therefore enters a **synthetic feature body** per run of tiles, from the first
tile's start edge to the last tile's end edge. Nothing draws it. It sits in draw
order immediately before its first tile and obeys the pickable-width exclusion on
the whole run (`syntenyTiledPick.test.ts`, `syntenyPickDrawOrder.test.ts`). A
pick-only instance kind would force both shaders and all three draw paths to
skip it.

Ribbon the geometry never emitted stays unpickable; see
[ideas/ready/a-merged-cigar-segment-is-labelled-by-its-last-op.md](../ideas/ready/a-merged-cigar-segment-is-labelled-by-its-last-op.md).

### Two things the numbers correct

**A whole-genome-zoom hover is free only because nothing is pickable.** Every
ribbon is sub-pixel, so `kept` is 0 and there is no tree; the exclusion made the
sub-pixel case free, not picking fast.

**Skew does not cost on the data where picking is slow.** `MAX_PAN_SKEW_PX`
cannot be tuned against the wide-hull arm; the collinear arm governs it, where
candidates grow ~1 per px of skew against a rebuild paid once. 2000px is a
conservative balance point.

### Probing picking yourself

- **Park the viewport mid-genome.** Near cumBp 0 the widened stab runs off the
  data and caps candidate growth for a reason unrelated to the index.
- **Do not take min-of-N over a loop that reuses the pick cache.** The first rep
  stores the index at the skewed pan and later reps answer warm, hiding a rebuild
  that happens on every real pan. Use a fresh cache per rep.
- **`kept` is not `instanceCount`.** The exclusion is scale-dependent, so a cost
  statement has to name the zoom.

### Parked against the per-candidate loop

- Push `minAlignmentLength` and `isInstanceInvisible` into `flatbush.search`'s
  `filterFn`: rejects nothing at the default `minAlignmentLength` of 0, so revisit
  gated on `minAlignmentLength > 0`.
- Drop the `Int32Array.sort()`: loses the descending walk's early exit, so
  measure how many candidates reach `buildFeaturePath` on a fragmented alignment
  first.
- `pickFeatureAtPoint` omits the `isMarker` arm of `isRibbonCulled`; harmless
  while the pickable-width exclusion keeps markers out of the index.
