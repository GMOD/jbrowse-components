# The per-base wall, and the sub-pixel bin that bounds it

## The wall

A `color` field of `baseQuality` or `base` is the one alignments pass that emits
an entry per *aligned base of every read*; every other pass emits one per event.
`extractPerBaseQuality` and `extractPerBaseLetter` write `PerBaseColumns`
(`features/alignedBaseWalk.ts`), nine bytes per entry. Nothing bounds the count
by the viewport: it is region span x depth, the span is the visible span widened
by half a screen each side (`planRegionFetch`), and an approved force-load
exempts the byte gate. `plugins/alignments/benches/perBaseWall.probe.ts`
measured it over the in-tree pacbio fixture at 33x zoom-out:

## What the bin is

`subPixelBinBp(bpPerPx)` in `packages/display-kit/src/subPixelBinBp.ts`: a power
of two `<= bpPerPx / 2`, and `1` below 4 bp/px. MAF's `encodeBinBp` calls it, so
the two displays cannot drift on `MIN_BINNED_BP_PER_PX`.

- `forEachAlignedBaseInRegion` takes a `binBp` stride. Windows anchor to
  **absolute genomic coordinate**, not to the op or the read; anchored per read,
  each row samples different columns and the wall breaks into per-row stripes.
- The display resolves `perBaseBinBp` off the **debounced** `coarseBpPerPx` and
  returns `1` in every scheme that is not `perBase` in `COLOR_SCHEMES`.
- It rides to the worker as a **call-site RPC argument**, like `byteLimit`, not
  as an `rpcProps` field: a zoom-swinging value in the payload is a
  `SettingsInvalidate` that drops every fetched region
  ([REGION_TOO_LARGE.md](REGION_TOO_LARGE.md) §"How the verdict is built").
  `zoomFetchArgs` carries the per-region half, and `dataSuperseded` keeps an SVG
  export from sampling data the settled zoom has moved past.

The count is bounded by `4-8 x canvasWidthPx x depth`.

**Do not key the fetch on live `bpPerPx`.** `FetchVisibleRegions` throttles at
600ms rather than settling, so a live key hands each throttled run the bin of a
zoom the gesture is only passing through, and each run refetches the one
pipeline whose extract is the OOM. `livePerBaseBinBp`'s JSDoc has the argument;
`dataSuperseded` is the reader that wants the live bin.

Both controls are byte-identical. `perBaseQuality` is visually equivalent at
every zoom captured. `perBaseLetter` is not: muddy olive becomes vivid stripes.

**Mechanism.** Canvas2D floors a cell to 1 CSS px while samples sit `binBp`
apart, so `bpPerPx / binBp` cells composite into one pixel and the pixel reports
roughly their mean. Quality colours are a narrow ramp, so the mean is close to
any single draw. Base letters are four widely separated hues, so 38 of them
(before the bin, at 37.9 bp/px) average to mud and 2 (after) do not.

**Canvas2D blends; the GPU largely overwrites.** `pileupCellX` snaps each cell
to a whole pixel column and the winner covers it outright:

The blend mechanism therefore describes the Canvas2D arms only. The two
backends disagree on this mode, and nobody intends to fix it:
[CROSS_BACKEND_GATE.md](CROSS_BACKEND_GATE.md) §"The per-base wall" holds the
numbers and the recipe, and the gate deliberately has no per-base scene.

`binBp` sits in `(bpPerPx/4, bpPerPx/2]`, so the surviving overdraw is a
constant 2-4x at every zoom. The bin caps compositing depth and never removes it.

The ceiling is the number of octaves crossed while `binBp > 1`, and the two
debounces (`coarseBpPerPx`, `FetchVisibleRegions`) collapse a click train or
slider drag to one to three calls, each a strict subset of the last. A pan that
leaves the buffer is a refill, not octave traffic.

**A zoom cannot cancel.** `planRegionFetch` answers `idle / inFlight` while
`isLoading`, so an octave crossed mid-fetch waits, commits under its stale
`fetchInputs` stamp, and issues the next off `fetchGeneration`. The abort
rotation is never reached from a zoom. The cancel that does exist
(`DisplayedRegionsChange` or `SettingsInvalidate` through `clearAllRpcData ->
cancelFetch -> controller.abort()`), fired by hand 80ms into the refetch:

## Scope: what the bin does not touch

Every **sparse** mark: mismatches, indels, SNP columns, modifications, arcs.
`featureFrequencyThreshold`, the frequency lerp and `extendToMinWidthX` already
handle them, and [MAF_SUBPIXEL_CELLS.md](MAF_SUBPIXEL_CELLS.md) records why a
point event stays opaque when a screen holds more bases than pixels.
