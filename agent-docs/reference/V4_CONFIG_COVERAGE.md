## What a verdict means

- **clean**: no finding about spelling.
- **warn**: every v4 spelling present has a `retired` lift or a migration
  (`lifted`), or a lift that reads the key and drops it (`dropped`, reported as
  "never read").
- **fail**: `jbrowse validate` exits 1 on a key or type no lift knows
  (`unmapped`) or a value shape it refuses (`shape`). Every config in the corpus
  opens in the app: an unmapped key drops, with a console line on a closed
  display schema (ADR-221) and with none elsewhere.
- `plugin`, `reference` and `lint` (any other warning) findings never set a
  verdict. `MyGeneV3Adapter` and `UCSCAdapter` come from the plugins
  `config_demo.json` declares; volvox's `wombat` and `volvox_del2` tracks and
  `bad_config_test` are deliberate error fixtures. The validator fetches
  nothing, so a missing local file never counts.
- A type v4.3.0 documented under `website/docs/config/` counts as `unmapped`
  rather than `plugin`, which is how `LinearLollipopDisplay` lands there.

## Worth a lift: a color or height drops

- **`colorBy` on `MultiLinearVariantDisplay`** names the sample-metadata
  attribute that colors the rows on load, the setting v5 spells `rowColor`.
  `LinearMultiSampleVariantDisplay`'s `retired` drops it
  (`colorBy: () => ({})`); `colorBy: field => (field ? { rowColor: field } : {})`
  keeps the color.
- **A session's `trackDisplayMode`** on `LinearBasicDisplay` (`compact`) is the
  feature height preset the config slot `displayMode` holds now. A
  `trackDisplayMode` entry in the display's `retiredState`, beside
  `jexlFiltersSetting`, keeps it, through the `normalizeDisplayMode` the config
  side's `renderer.displayMode` already passes.
- **A session's `snpCovHeight`** on `LinearAlignmentsDisplay` is the coverage
  band's height, now `coverage.height`, and belongs in the alignments
  `retiredState` beside the coverage axis keys. Both corpus sessions hold the v4
  default, so the corpus shows no visible loss.

## Let drop, but say so

Every v4 `jbrowse text-index` run wrote `textSearchAdapterId` and
`metaFilePath` into a `TrixTextSearchAdapter`, whose schema declares no
`retired` map, so both fail validation and drop at load with no console line.
Neither changes a search: the adapter caches by a hash of its config, and
nothing reads `_meta.json`. A `() => ({})` entry for each, and for v4's `tracks`
slot, turns the error into a "never read" warning, the release claim's wording.
The two keys fail more corpus configs than any other spelling.

## Validator gaps: the app lifts these, `jbrowse validate` errors

- **`minorAlleleFrequencyFilter`**: the multi-sample display's
  `preProcessSnapshot` lifts it into a `filter` predicate, outside `retired`.
  The manifest generator reads `retired` and probes its `LEGACY_CANDIDATES`,
  so a key lifted anywhere else reads as unknown.
- **A session's flat `LinearSyntenyView.tracks`**: `liftViewLevelTracks` moves
  built track snapshots into `levels[0]`; the schema wants one array per level.
- **`renderer` on `LinearArcDisplay`**: the retired type's `migrate` strips it
  (ADR-163) before the mark display's schema sees the entry. The validator
  resolves the alias but runs no `migrate`. A hand-written arc `height` jexl
  drops with it.
- **`windowSize` and `windowDelta` on a reference sequence track's
  `LinearGCContentDisplay`**: `liftGCSettings`, a `Core-preProcessTrackConfig`
  hook, removes the whole display, since v5 draws GC content as a separate
  track. The validator runs no track preprocessor.

## Let drop: cosmetic v4 settings

Each session key below fails validation, and the session model drops it at load
with no console line.

- `session.margin`; `DotplotView`'s `borderSize`, `fontSize`, `tickSize`,
  `htextRotation`, `vtextRotation` and `hview`/`vview`
  `interRegionPaddingWidth`; `viewTrackConfigs` on both comparative views.
- `LinearSyntenyView`'s `drawCurves` (now `mark.interpolate: 'bump'`),
  `linkViews`, `showIntraviewLinks` and `interactiveOverlay`.
- `LinearGenomeView`'s `showGridlines`, `bookmarkHighlightsVisible` and
  `bookmarkLabelsVisible` (`upgrading_v5.md` documents the highlight keys).
- `LinearAlignmentsDisplay`'s `lowerPanelType`; every corpus session holds the
  default.

The `dropped` rows, `sequenceAdapter`, `rpcDriverName` and the Hi-C
`resolutionMultiplier`, are config keys a `retired` lift already reads and
drops, so they warn.

## Not v4 spellings: v4.3.0 dropped them too

v4.3.0's schemas and models declared none of the keys below, so v4 ignored them
as v5 does:

- `gffLocation` on `Gff3TabixAdapter`, in two config-guide snippets (v4 spelt it
  `gffGzLocation`).
- `hasRefreshToken`, `BamAdapter.metadata`, a track-level `autoscale`, a trix
  adapter's `assemblies`, and root-level `widgets`, `activeWidgets` and
  `connectionInstances`.
- Session keys older than v4: `session.width`, `session.connections`,
  `headerHeight`, `hideControls`, `middleComparativeHeight`, `interactToggled`,
  a synteny view's `height`, a dotplot's `width`, `trackSelectorType` on a
  breakpoint split view, and a display's `jexlFilters` (v4's state spelt it
  `jexlFiltersSetting`).
- `defaultSession.view` in `products/jbrowse-img/data/config.json`, the
  single-view session jbrowse-img read before react-app2. jbrowse-img lifts it
  for `--session` but not from a config's `defaultSession`.
