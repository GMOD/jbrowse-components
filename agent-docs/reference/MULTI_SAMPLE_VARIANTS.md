# Multi-sample variant genotypes: the code pipeline

The per-feature x per-sample loop in `computeVariantCells.ts` runs 10⁸+ times
on a real panel. The rules are in `plugins/variants/src/CLAUDE.md`; this doc
holds the mechanism behind them.

## Genotypes reach the cell loops as codes, never as strings

`analyzeVariants` makes one `processGenotypes` pass per feature and interns
`genotypeCodes`, accumulates `samplePloidy`, folds the legend flags and counts alleles for
the MAF and missingness filters. The cell loops index codes by a source's column
(`buildSourceSampleIndices`) and key style memos by code. A per-feature
`Record<sampleName, genotype>` from `GENOTYPES()` is the shape this replaced.

With a MAF or missingness threshold set, the counting pass still runs first: a threshold
keeps a few percent of a window and analysis costs more per cell than counting, so fusing
the passes measured slower.

## Nothing on the per-cell path may be keyed by sample NAME

A string-hash lookup per cell is 10⁸ hashes. `samplePloidy` accumulates into typed arrays
by column, then folds into the name-keyed `Record` once through `accumulatePloidy`. The
fold runs **before** the record block, which reads `samplePloidy`'s keys to extend the
canonical order. Ploidy 0 means "column never reported".

`packGenotypeKey` packs a genotype of at most 4 ASCII chars into one int for the site
memo. A non-ASCII code unit declines to pack rather than truncating, since a truncated
key could collide and paint the wrong cell.

## A code's column is the canonical `sampleNames` position

Never `processGenotypes`' `sampleIdx`, which numbers samples against the header of the file
*its own* feature came from, while `sampleNames` is the union of every header in the fetch.
They disagree for `SplitVcfTabixAdapter` when per-contig files order or omit samples
differently. `buildHeaderRemap` translates and answers `undefined` when they agree.

Writing `codes[sampleIdx]` silently files each genotype and ploidy against a neighbouring
sample on a multi-contig view, since every row still holds a real genotype.
`phaseSetReader` reads PS through the same callback and needs the same translation.

`makePhaseSetReader` is shared by both cell loops so the absent/malformed rules cannot
drift: an absent column, an empty field and `.` fall back to allele coloring; an
unparseable id is NaN and paints hue 0, matching `SAMPLES()`' `+` coercion.

## Codes are Uint32

Uint16 capped the dictionary at 65535 distinct genotype strings, reachable on a decomposed
pangenome callset. **0 means "no call"**, so a genotype interned past the cap to 0 would
not paint.
