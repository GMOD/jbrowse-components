# Multi-sample variant genotypes: the code pipeline

The per-feature x per-sample loops in `computeVariantCells.ts` and
`computeVariantMatrixCells.ts` run 10⁸+ times on a real panel. The rules that
follow are in `plugins/variants/src/CLAUDE.md`; this doc holds the mechanism
behind them.

## Genotypes reach the cell loops as codes, never as strings

`analyzeVariants` makes one `processGenotypes` pass per feature (the `@gmod/vcf`
callback that reports a genotype as a range into the line) and from it interns
`genotypeCodes`, accumulates `samplePloidy`, folds the legend flags and counts
each site's alleles for the MAF and missingness filters.

The cell loops index those codes by a source's column
(`buildSourceSampleIndices`, resolved once per pass) and key their style memos by
code, so a genotype string is materialized once per (site, distinct genotype)
rather than once per cell. A per-feature `Record<sampleName, genotype>` built by
`GENOTYPES()` and walked three more times was the shape this replaced.

## The filter's allele counts ride the analysis memo

The per-site memo groups samples by distinct genotype, so `countGenotypeAlleles`
counts each distinct genotype once, weighted. That retired
`getFilteredVariants`' own `processGenotypes` pass on the default path.

**With a MAF or missingness threshold set, the counting pass still runs first.**
A threshold typically keeps a few percent of a window, and analysis costs more
per cell than counting, so fusing the passes measured slower. Count first and
analyze the survivors. Ploidy folds in from the sites the analysis walks.

## Nothing on the per-cell path may be keyed by sample NAME

The callback runs once per cell, so a string-hash lookup is 10⁸ hashes on a real
panel. `samplePloidy` accumulates into typed arrays indexed by the column the
callback holds, then folds into the name-keyed `Record` once after the pass
through `accumulatePloidy`, the same function the record path uses. The fold runs
**before** the record block, which reads `samplePloidy`'s keys to extend the
canonical order. Ploidy 0 means "column never reported", which keeps a
genotype-less sample out of `samplePloidy`.

## The site memo probes by packed int where it can

`packGenotypeKey` folds a genotype of at most 4 ASCII chars into one int, so
recognizing a repeat is an int compare. Longer genotypes key 0 and keep the range
compare. A non-ASCII code unit **declines to pack** rather than truncating,
because a truncated unit could collide with another genotype's key and paint the
wrong cell.

The codes, dictionary, sample order, ploidy/phasing and legend flags are
byte-identical across the change. **The packed key measured 1.02x alone** because
the name lookup masked it, and was worth another 1.15x once that went. Don't
re-evaluate either half in isolation.

## A code's column is the canonical `sampleNames` position

Never `processGenotypes`' `sampleIdx`, which numbers samples against the header
of the file *its own* feature came from, while `sampleNames` is the union of every
header in the fetch. The two agree for every adapter but `SplitVcfTabixAdapter`,
and disagree when per-contig files order or omit samples differently.
`buildHeaderRemap` translates header position to column and answers `undefined`
when they agree, so the common fetch pays nothing.

Writing `codes[sampleIdx]` files each genotype and ploidy against a neighbouring
sample on a multi-contig view, silently, since every row still holds a real
genotype. `phaseSetReader` reads PS through the same callback and needs the same
translation.

`makePhaseSetReader` is shared by both cell loops so the absent/malformed rules
cannot drift. An absent column, an empty field and `.` mean "no phase set" and
fall back to allele coloring. A present-but-unparseable id is NaN and paints hue
0, matching `SAMPLES()`' `+` coercion. GT is not read there; it comes from the
interned codes. An adapter that cannot report FORMAT ranges paints by allele.

## Codes are Uint32

Uint16 capped the dictionary at 65535 distinct genotype strings, reachable on a
decomposed pangenome callset where a multiallelic site's genotypes grow with the
square of the alt count. **0 means "this sample has no call"**, so a genotype
that interned past the cap to 0 would not paint.
