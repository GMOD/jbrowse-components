# Plugin ABI stability

Runtime plugins share the host's singletons (React, MST, `@jbrowse/core`), so
every name the host serves is ABI, and a removal fails at the plugin's runtime,
not at the host's build. In-tree consumers get the compiler; external plugins,
built against a published `@jbrowse/*`, get nothing. This is not a formal
stability policy; RFC-001 deferred one.

## The surfaces and their guards

- **`@jbrowse/core`'s published `exports` map, which nobody writes.**
  `packages/core/scripts/generateExports.mjs` derives it from import
  specifiers under `packages plugins products example-plugins`. A subpath
  stays published only while something there imports it, so deleting the last
  importer un-publishes it in the same commit with nothing said. No gate
  compares against the previous release; `preservedExports` in the script is
  the only lever that keeps a subpath with no in-repo importer.
- **The accumulating extension points fail quietest.** `addToExtensionPoint`
  excludes them in its type, so a rebuilt plugin gets a compile error naming
  `contributeToExtensionPoint`. A prebuilt bundle carries no types: the old
  callback returns its own single-element array in place of everyone else's
  entries. Nothing throws, and the plugins that lose entries are the other ones.

**A baseline per surface was tried and dropped.** Maintaining one per refactor
costs more than the removals it catches. Only `preservedExports` survives.

**The signature is as public as the name.** A required second argument breaks
a duck-typed caller as deleting the member does, so add plugin-facing
parameters optional, never required. The converse breaks subclasses: removing
a parameter from a base method makes an override with more required
parameters unassignable.

**Component props have no check.** Every checked surface is an exported name
or path, and a prop is neither. Dropping `slotProps` from `CascadingMenuProps`
is a compile error for a rebuilt plugin and a silently ignored prop for a
prebuilt bundle.

## The real cure: bound what external plugins can reach

An internal is safe to refactor only when it is unreachable, and nothing in tree
can prove an external plugin does not use it. By leverage: (1) split the runtime
surface into published and not, which ADR-128 did by making the published set
every exports-map subpath; (2) version the contract and fail loud at load time,
not built; (3) instrument deprecations with a warning getter, not built, and
only to accelerate removal, since telemetry sees only observed deployments; (4)
make the blessed extension points good enough that nobody reaches into
internals (`BaseLinearDisplay` leaked because no stable custom-display API
existed). "Nothing is removed" is not an iron law: the GPU rewrite removed the
legacy block stack and accepted the gdc/icgc breakage.

## Community plugin API decisions

The 2026-07 RFC-001 decisions that stand:

- **Cross-plugin coupling is a static import plus esbuild `globalExternals`.**
  `pluginManager.getPlugin('X').exports` is removed for new plugin code.
- **Canvas2D or GPU.** GPU earns its keep above roughly 100K features per
  frame. Below that, Canvas2D is simpler, spends no context budget
  ([GPU_PORTABILITY.md](GPU_PORTABILITY.md)) and is the path SVG export reuses.
  The backend decides, not the display type.
- **Primitives, not a framework.** No glyph-registration, spec-grammar or DSL
  layer: it would lose per-feature batching, conditional paths and custom
  hit-testing, and each mark keeps its varying part explicit
  ([ADR-040](../architecture-decision-records/adr-040-no-genome-quad-vertex-helper.md)).
- **No backwards compatibility for legacy-API plugins**
  (`linearWiggleDisplayModelFactory`, `FeatureRendererType`).
- **`bpPerPx` stays the MST single source of truth, with no decoupled 60fps
  zoom animation.** Three approaches failed: a volatile `pendingBpPerPx` with a
  debounced commit, animating only the `bpRangeX`/`viewBp` uniform, and a
  discrete fetch-level tile model with a continuous GPU transform.
  **Decoupling needs its own ADR and an explicit go-ahead.**

## Measured: what v5 cost one out-of-tree plugin

Apollo (`GMOD/Apollo3`, `jbrowse_5`) is the one substantial external plugin
tracking main. It pins jbrowse by committed tarball, so typechecking its same
source against its own pin and against main gave a clean control.

- **A core dependency bump on a package whose types cross the plugin boundary is an ABI event.**
  When core's `@jbrowse/mobx-state-tree` and `@mui/material` ranges moved
  without the plugin's, a second copy of each appeared and produced hundreds of
  errors naming neither duplication nor the cause: MST reports `[$type]`
  missing, MUI reports palette members missing, because a module augmentation
  cannot reach a second copy of the module it augments. No checker sees this
  class
  ([ideas/waiting-on-a-call/a-dependency-bump-is-an-abi-event.md](../ideas/waiting-on-a-call/a-dependency-bump-is-an-abi-event.md)).

## Ledger: behavior changes external plugins inherit

A change to how core interprets what a plugin declares reaches every external
plugin with no import to grep and no compile error. Each entry carries the
opt-out.

- **Config slot overrides merge over `baseConfiguration`** (`mergeSchemaDefinition`). An override inherits every field it leaves out (`description`, `advanced`, `contextVariable`, `validate`, `model`); an override that relied on replacement to shed one gains it back. **Opt-out: state the field (`advanced: false`).** Sub-schemas and constants still replace wholesale.
- **`RpcMethodType.deserializeArguments` runs in the base `invoke`.** A plugin `execute` that still calls it runs it twice, so **an override must be idempotent**: replace wholesale or test the type before rebuilding (the filters override checks `instanceof SerializableFilterChain`). A non-idempotent override fails inside plugin code with no core frame. **Opt-out: drop the call from `execute`.**
- **`@jbrowse/core/data_adapters/dataAdapterCache` is now served**, and this one runs the opposite direction: *adding* to `list.ts` has the consequence. A deep path absent from the list is bundled, not host-bound; serving it makes the plugin's **next rebuild** host-bound, and it error-pages on any host older than this release. A plugin that deep-imported `getAdapter` had a second adapter cache in the worker that `freeAdapterResources` never reached, so adapters lived as long as the worker. **Opt-out: keep bundling** by dropping the path from the plugin's globals map before `globalExternals` sees it (msaview's `SHAPE_VARIES_BY_HOST` in `esbuild.mjs`). Gate the publish with `pnpm host-compat`, the only check that sees this class. General rule: **an ABI addition is safe for the host and every published bundle, but it is a version floor for the next build of any plugin already reaching that path.**
- **The observation unit is one `unit` slot.** The alignments display lost `linkedReads`, `setLinkedReads` and `isChainMode`, and `@jbrowse/plugin-alignments` exports `AlignmentsUnit` where it exported `LinkedReadsMode`; the multi-sample variant display lost `renderingMode` and `setPhasedMode`. A plugin reading those members gets `undefined`, and one calling the setters throws. A config or session spelling either old slot still loads, through the schemas' `retired` lifts. **Opt-out: read `display.unit` (`'read' | 'chain'`, `'sample' | 'haplotype'`) and write it with `setUnit`.**
- **An RPC call cannot be pinned to a driver.** `BaseDisplay` lost `rpcDriverName`, `effectiveRpcDriverName`, `setRpcDriverName` and `parentDisplay`; `baseTrackConfig` lost its `rpcDriverName` slot; `RpcRouting` left `RpcCallArgs`. A plugin reading the display members gets `undefined`, and a config carrying the slot gets an unknown slot JBrowse ignores. No opt-out. A plugin cannot supply a driver either: `registerDriverFactory`, `driverFactories`, `driverObjects` and `RpcDriverFactory` are gone, since `BaseRpcDriver` has no `exports` entry. ADR-086.
