# Plugin ABI stability

Runtime plugins share the host's singletons (React, MST, `@jbrowse/core`), so
every name the host serves is ABI, and a removal fails at the plugin's runtime,
not at the host's build. In-tree consumers get the compiler; external plugins,
built against a published `@jbrowse/*`, get nothing. This is not a formal
stability policy; RFC-001 deferred one.

## The surfaces and their guards

- **The runtime registry is the exports maps**
  ([ADR-128](../architecture-decision-records/adr-128-the-runtime-abi-is-the-exports-maps.md)).
  `scripts/generateReExports.ts` writes `reExports.generated.json`; a removal is
  a diff there, and `ABI_REMOVED_NAMES` (`website/scripts/generate-abi-removals.ts`)
  fails `pnpm autogen --check` until someone describes it.
  `scripts/check-published-plugins.ts` and `scripts/check-plugin-porosity.ts`
  cover store bundles and the exemplar plugin.
- **`@jbrowse/core`'s published `exports` map, which nobody writes.**
  `packages/core/scripts/generateExports.mjs` derives it from import
  specifiers under `packages plugins products example-plugins`. A subpath
  stays published only while something there imports it, so deleting the last
  importer un-publishes it in the same commit with nothing said. No gate
  compares against the previous release; `preservedExports` in the script is
  the only lever that keeps a subpath with no in-repo importer.
- **The session and the plugin `exports` objects** have no presence check.
  `pluginFacingSessionApi.test.ts` pins and calls the session members published
  bundles use, which catches a surviving member with a changed signature.
- **The accumulating extension points fail quietest.** `addToExtensionPoint`
  excludes them in its type, so a rebuilt plugin gets a compile error naming
  `contributeToExtensionPoint`. A prebuilt bundle carries no types: the old
  callback returns its own single-element array in place of everyone else's
  entries. Nothing throws, and the plugins that lose entries are the other ones.

**A baseline per surface was tried and dropped.** Maintaining one per refactor
costs more than the removals it catches. Only `preservedExports` survives.

**The signature is as public as the name.** A required second argument breaks
a duck-typed caller as deleting the member does, so add plugin-facing
parameters optional, never required. The converse breaks subclasses: removing
a parameter from a base method makes an override with more required
parameters unassignable.

**The exemplar plugin's imports are part of the derivation.**
`example-plugins/score-example` is the stack an external author copies
([ADR-030](../architecture-decision-records/adr-030-render-core-package-static-import-only.md)),
so `generateExports.mjs` scans it. Its `defineMark` options, `MarkShape`
members, the `barMark` shape and the frame plan (`planMarks`,
`drawPlannedPasses`) are third-party ABI, not in-tree convention.

**Component props have no check.** Every checked surface is an exported name
or path, and a prop is neither. Dropping `slotProps` from `CascadingMenuProps`
is a compile error for a rebuilt plugin and a silently ignored prop for a
prebuilt bundle.

## What has left the session and the plugin `exports` objects

Neither surface is checked against a published bundle.

- **The session**, reached by member lookup (`'x' in session`), so nothing fails at build time:
  - `removeReferring`, `prepareToBreakConnection`, `hasWidget` — deleted. `hasWidget` is `session.widgets.has(id)`.
  - `editTrackConfiguration` (web) — deleted; `editConfiguration` is the same action.
  - `setDefaultSession` (web) — deleted; the action is the root's, `session.root.setDefaultSession()`.
  - `getReferring` — **still there, with a signature a v4 caller does not satisfy.** It takes a `trackId` string, not the config object. A v4 caller passing the object matches nothing and gets `[]`, so it concludes no view refers to the track and closes it out from under whatever shows it.
- **`@jbrowse/product-core`'s `Session` barrel**, a named allowlist rather than `export *`:
  - `DialogQueueSessionMixin`, `isSessionWithDialogs`, `SessionWithDialogs`, `SessionWithDialogsType` — folded into `BaseSessionModel`, which declares the dialog members itself. A product assembling its own session composes `BaseSessionModel`.
- **All four plugin `exports` objects** (`AuthenticationPlugin`, `DataManagementPlugin`, `LinearGenomeViewPlugin`, `WigglePlugin`). A runtime plugin does not read what an `exports` object held off the host; it is a named export of the plugin package. `LinearGenomeViewPlugin.exports` had carried `BaseLinearDisplay` and `BaseLinearDisplayComponent`: a v4 plugin composing `exports.BaseLinearDisplay()` throws in `install`, so its track type never registers and a saved session opens with the track absent.
- **`@jbrowse/plugin-linear-genome-view` type exports** `LayoutRecord` and `Layout` — break a build, not a session. `@jbrowse/plugin-breakpoint-split-view` declares its own `LayoutRecord`.

## The real cure: bound what external plugins can reach

An internal is safe to refactor only when it is unreachable, and nothing in tree
can prove an external plugin does not use it. By leverage: (1) split the runtime
surface into published and not, which ADR-128 did by making the published set
every exports-map subpath; (2) version the contract and fail loud at load time,
not built; (3) instrument deprecations with a warning getter, not built, and
only to accelerate removal, since telemetry sees only observed deployments; (4)
make the blessed extension points good enough that nobody reaches into
internals (`BaseLinearDisplay` leaked because no stable custom-display API
existed). "Nothing is removed" is not an iron law: the GPU rewrite removed the
legacy block stack and accepted the gdc/icgc breakage.

## Community plugin API decisions

The 2026-07 RFC-001 decisions that stand:

- **Names as shipped.** `RenderLifecycleMixin` (`packages/render-core/`),
  `attachRenderingBackend`, `stopRenderingBackend`, `useRenderingBackend` and
  `createRenderingBackend` replaced the RFC's GPU-specific names. Canvas2D
  composes the same `attachRenderingBackend({ upload, render })` shape.
  [GPU_RENDERING.md](GPU_RENDERING.md) indexes the lifecycle docs.
- **Cross-plugin coupling is a static import plus esbuild `globalExternals`.**
  `pluginManager.getPlugin('X').exports` is removed for new plugin code.
- **Canvas2D or GPU.** GPU earns its keep above roughly 100K features per
  frame. Below that, Canvas2D is simpler, spends no context budget
  ([GPU_PORTABILITY.md](GPU_PORTABILITY.md)) and is the path SVG export reuses.
  The backend decides, not the display type.
- **Primitives, not a framework.** No glyph-registration, spec-grammar or DSL
  layer: it would lose per-feature batching, conditional paths and custom
  hit-testing, and each mark keeps its varying part explicit
  ([ADR-040](../architecture-decision-records/adr-040-no-genome-quad-vertex-helper.md)).
- **No backwards compatibility for legacy-API plugins**
  (`linearWiggleDisplayModelFactory`, `FeatureRendererType`).
- **`bpPerPx` stays the MST single source of truth, with no decoupled 60fps
  zoom animation.** Three approaches failed: a volatile `pendingBpPerPx` with a
  debounced commit, animating only the `bpRangeX`/`viewBp` uniform, and a
  discrete fetch-level tile model with a continuous GPU transform.
  **Decoupling needs its own ADR and an explicit go-ahead.**

## Measured: what v5 cost one out-of-tree plugin

Apollo (`GMOD/Apollo3`, `jbrowse_5`) is the one substantial external plugin
tracking main. It pins jbrowse by committed tarball, so typechecking its same
source against its own pin and against main gave a clean control.

- **A core dependency bump on a package whose types cross the plugin boundary is an ABI event.**
  When core's `@jbrowse/mobx-state-tree` and `@mui/material` ranges moved
  without the plugin's, a second copy of each appeared and produced hundreds of
  errors naming neither duplication nor the cause: MST reports `[$type]`
  missing, MUI reports palette members missing, because a module augmentation
  cannot reach a second copy of the module it augments. No checker sees this
  class
  ([ideas/waiting-on-a-call/a-dependency-bump-is-an-abi-event.md](../ideas/waiting-on-a-call/a-dependency-bump-is-an-abi-event.md)).
- **A registry declaration constrains only a plugin whose program already
  contains the module the declaration lives in.** `Core-extendWorker` broke at
  runtime and typechecked clean: `@jbrowse/core/rpc/WebWorkerRpcDriver` had no
  `exports` entry, so the handle type was unimportable and the augmentation
  never loaded. With the key absent from the registry, `addToExtensionPoint`
  fell to its untyped overload, which infers the parameter from the callback,
  so the wrong shape defined the check.
- **Every extension-point declaration site has this property.** Seven more
  were unreachable: each was imported as a value inside `install()`, which tsc
  erases from the declarations. The fix is re-exporting a name from the
  package entry, as `check-declaration-leaks.ts` prescribes.
- **Measure reachability in `esm/`, never `src/`.** Core's `import type {}`
  side-effect imports survive emit because the augmentation targets
  `PluginManager`; the identical line in a plugin is elided as unused.
  `scripts/check-extension-point-reachability.ts` is the gate, beside
  `check-declaration-leaks.ts` in the post-build CI step.
- **The typed registry works where reachable**: its diagnostics name the
  replacement (`listenToExtensionPoint`, `contributeToExtensionPoint`) with no
  doc needed.

## Ledger: behavior changes external plugins inherit

A change to how core interprets what a plugin declares reaches every external
plugin with no import to grep and no compile error. Each entry carries the
opt-out.

- **Config slot overrides merge over `baseConfiguration`** (`mergeSchemaDefinition`). An override inherits every field it leaves out (`description`, `advanced`, `contextVariable`, `validate`, `model`); an override that relied on replacement to shed one gains it back. **Opt-out: state the field (`advanced: false`).** Sub-schemas and constants still replace wholesale.
- **`setPreferenceOverride`, `clearPreferenceOverrides` and `setScrollZoom` are required on `AbstractSessionModel`.** A plugin building its own session from scratch fails to typecheck. **Opt-out: compose `BaseSessionModel`**, or declare them.
- **Display-type defaults and `promotable` slots are gone**
  ([ADR-111](../architecture-decision-records/adr-111-display-type-defaults-backed-out.md)). A `promotedBase: V` on a `maybe*` type becomes `defaultValue: V` on the plain type. No opt-out.
- **`createTimeGate` thins clock reads in loop callbacks** (`createAbortBreakpoint`, `createProgressReporter`). Progress and cancellation can land up to ~1/8 interval later, one more interval after a sudden slowdown. **Opt-out: call `checkAbortSignal` directly** at a point that must not be thinned.
- **`RpcMethodType.deserializeArguments` runs in the base `invoke`.** A plugin `execute` that still calls it runs it twice, so **an override must be idempotent**: replace wholesale or test the type before rebuilding (the filters override checks `instanceof SerializableFilterChain`). A non-idempotent override fails inside plugin code with no core frame. **Opt-out: drop the call from `execute`.**
- **Six `RpcMethodType` methods lost `rpcDriverClassName`** (`serializeArguments`, `serializeNewAuthArguments`, `deserializeArguments`, `invoke`, `execute`, `deserializeReturn`). An override declaring it now fails to typecheck. **Opt-out: delete the parameter**, or declare it optional to compile against both releases.
- **`RpcManager.call` has no fourth `options` parameter**, nor do `BaseRpcDriver.call` and `transport`. `MainThreadRpcDriver` dropped it and `WebWorkerRpcDriver` spread it over its own. **Opt-out: move the field into `args`.** A `BaseRpcDriver` subclass declaring `options` breaks.
- **`deserializeReturn` is typed off the registry.** An override returning what the entry does not declare is a compile error; one that called `super` to strip `rpcResult` should call `unwrapRpcResult` (`@jbrowse/core/util/librpc`). **Opt-out: leave `RpcMethodType` unparameterized.**
- **`RpcMethodType` and the rename-region bases take one type parameter.** `RpcMethodType<'X', Y>` is an arity error; drop the `Y`, since the registry entry carries the wire return.
- **`DiagonalizeRpcBase` and `executeDiagonalize` left `@jbrowse/synteny-core`.** Share an RPC body as a function, never as a base generic over the key. **Opt-out: extend `RpcMethodType<'YourKey'>` and `await runDiagonalize(...)`.** A static export beside a dynamic import puts the module in the main chunk, silently, for the plugin that imported it statically.
- **`detectAssembliesSwapped`, `detectDisplayAssembliesSwapped`, `LEGEND_CHIP_ALPHA_FLOOR` and `blendOverWhite` left `@jbrowse/synteny-core`.** **Opt-out: `installAssemblySwapCheck(self, …)` and `legendChipColor(color, alpha, ground)`.**
- **`legendChipColor` takes the band's ground as a third argument** (`blendOverGround`). **Opt-out: pass `'#fff'`**, byte-identical to the old call.
- **`RpcClient.call` takes no transfer list.** Transferables flow only worker to main; `RpcServer.emit` keeps its list.
- **`@jbrowse/core/data_adapters/dataAdapterCache` is now served**, and this one runs the opposite direction: *adding* to `list.ts` has the consequence. A deep path absent from the list is bundled, not host-bound; serving it makes the plugin's **next rebuild** host-bound, and it error-pages on any host older than this release. A plugin that deep-imported `getAdapter` had a second adapter cache in the worker that `freeAdapterResources` never reached, so adapters lived as long as the worker. **Opt-out: keep bundling** by dropping the path from the plugin's globals map before `globalExternals` sees it (msaview's `SHAPE_VARIES_BY_HOST` in `esbuild.mjs`). Gate the publish with `pnpm host-compat`, the only check that sees this class. General rule: **an ABI addition is safe for the host and every published bundle, but it is a version floor for the next build of any plugin already reaching that path.**
- **An RPC call cannot be pinned to a driver.** `BaseDisplay` lost `rpcDriverName`, `effectiveRpcDriverName`, `setRpcDriverName` and `parentDisplay`; `baseTrackConfig` lost its `rpcDriverName` slot; `RpcRouting` left `RpcCallArgs`. A plugin reading the display members gets `undefined`, and a config carrying the slot gets an unknown slot JBrowse ignores. No opt-out. A plugin cannot supply a driver either: `registerDriverFactory`, `driverFactories`, `driverObjects` and `RpcDriverFactory` are gone, since `BaseRpcDriver` has no `exports` entry. ADR-086.
- **The `@material-ui/*` aliases are no longer served.** `jbrowse-plugin-reactome` reads them at module scope and now fails to load. **Opt-out: none; rebuild against `@mui/material`.**
- **A shader's text is reached through `SOURCE`, its bindings through `BINDINGS`, and its texture filter through `//! texture-filter:`** (`@jbrowse/render-core/slangPass`, `/hal`, `/computePipeline`). `ShaderModule` takes `SOURCE` and `BINDINGS`; `PipelineDescriptor` takes `source` and `bindings`; the WebGPU bind-group layout comes from each binding's `stages`; `SlangPassOpts.textures` is gone; `WebGL2Hal.create` replaces the constructor. A shader generated earlier lacks them, and `slangPass` throws naming the regeneration (without it each GPU rung threw and the display drew on Canvas2D, unexplained). **Opt-out: none; regenerate with `jbrowse-build-shaders`.** The type narrowing, like the component-prop case, escapes the name-based checks. render-core is `@experimental` until it freezes under semver (ADR-030) and v5 ships no migrations.
- **A render lifecycle's callbacks must answer `releaseTargets`** (`RenderLifecycleMixin`, `installUpload`). The render autorun frees the 4x MSAA attachment of an off-screen canvas. In-tree, `installUpload` supplies it. **Opt-out: call `installUpload`.**
