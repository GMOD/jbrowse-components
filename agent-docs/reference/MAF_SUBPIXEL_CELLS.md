# What a sub-pixel MAF cell looks like

MAF cells are run-merged, so a sub-pixel cell means "this run is shorter than a
pixel" — the normal case for a multiple alignment at any interesting zoom, not
an edge one. At `ctgA:1-4000` on volvox (~3.25 bp/px) `subPixelBinBp` is 1, so
both backends walk every base and a 1-bp cell is 0.31 CSS px.

**Neither backend floors one.** `MAF_ROW_MARK` declares `minWidthPx: 0`, which
makes the shader's `extendToMinWidthX` a no-op and leaves `minCellDenomPx`
deciding nothing; the `span` painter draws cells at their natural sub-pixel
width. The rasteriser
blends them, and the blend is the answer.

The multi-row feature painter draws the same `rowRect` module and *does* floor
(`MULTI_ROW_MIN_CELL_PX`). That asymmetry is deliberate and turns on whether the
marks tile: a MAF cell sits in a run of its neighbours and the run is what is
read, while a chromosome painting's features are sparse intervals with white
paper beside them, where a sub-pixel tick reads as nothing at all.

## Why: measured 2026-08-31

The rule was picked against a ground truth rather than argued. The no-floor
render was shot at dpr 4 — where a 1-bp cell is 1.25 device px, so nothing is
floored away — and box-downsampled by 4. That is the base-weighted mix a dpr-1
pixel should hold, computed by the renderer under test. Distance from it is a
number, over the rows band:

- **A floor over-states.** Every short run claims a whole pixel at full
  saturation, so a noisy stretch becomes a wall of hard bars where the truth is
  a soft mixture — and it invents contrast, because widened cells overwrite each
  other instead of sharing the pixel.
- **A device-px floor moves with the monitor.** MAF's floor was 1 device px, so
  0.5 CSS px at dpr 2, and the same alignment carried 39% less colour on a
  retina screen. Removing the floor removed that in the same change.
- **Floor + span alpha washes out.** It recovers most of the over-statement but
  still spreads each run over a pixel it does not occupy, blurring the column
  structure the display exists to show.
- **4x MSAA was not a problem.** The worry was that it quantises a sub-pixel
  cell's coverage onto 0 or 1 sample positions. Adjacent cells are
  non-overlapping primitives, so each writes its own samples and the resolve
  averages them; nothing dropped out.

`products/jbrowse-web/browser-tests/probe-maf-subpixel.ts` re-takes the shipped
rule's row and the Canvas2D row against a freshly captured truth. It needs a
real GPU — it passes `--use-gl=angle`, and under swiftshader the numbers belong
to a different rasteriser.

## Wiggle density writes 1.5 px, and on a tiling that paints the same picture

`wiggleDensity.slang` writes `MIN_FILL_WIDTH_PX` into the `minCellPx` this page
leaves at 0, over bins that tile the row. Three reviews have read that as the
contradiction it looks like. It is not one: `extendToMinWidthX` grows a quad off
its own START edge, so the next bin's quad covers the growth, and the last quad
covering a sample point is the bin holding that point under either rule. The two
renderings are the same image — not close, identical — for any sample pattern,
provided the bins arrive in coordinate order, which every quantitative adapter
emits and nothing in the wiggle path re-sorts.

Measured on the raw section of `volvox-sorted.bam.coverage.bw` at 3.25 bp/px,
where a 1-bp record is 0.308 CSS px:

The audit's own scene — 4 kb across 1000 px, 0.25 px a bin — ties at exactly
0.00, because an integer bp/px puts each bin on its own 4x sample position.
3.25 bp/px is published instead so the tie cannot be read as an artefact of that
alignment.

Where the bins do NOT tile — a bedGraph with gaps, a sparse quantitative source
— density is the multi-row painter's case rather than MAF's, and the floor costs
what a floor costs: five times the row's honest ink. What it buys is the only
legibility those marks have. At 4 bp/px the unfloored sparse row is worse than
faint on a single-sampled target: every 0.25 px mark misses every pixel centre
and the row comes back blank white.

`plugins/wiggle/src/shared/shaders/densityMinWidth.test.ts` pins both halves, so
a floor moved onto either spelling fails there rather than in a fourth review.

## Why `sizeAlpha` is not the analogue

The floor+alpha shape is what `plugins/alignments` ships
(`alignmentsUniforms.slang`), and it is deliberately indels-only there: a
mismatch is a point event whose whole value is being visible when a screen holds
more bases than pixels. A MAF cell is per-base identity — the mismatch analogue
— and `sizeAlpha` exists to give back the ink a *widened* mark took, so applying
it to a cell drawn at natural width double-counts the narrowness. The
measurement agrees: the wash-out is visible in the numbers.
