## Behavior

- **No workers start until a chunk of at least `POOL_MIN_DECOMPRESSED_BYTES`
  inflated bytes arrives.** A fixture of only small chunks measures nothing,
  silently: volvox never engages the pool.

So **1.55-2.02x<!--m:bgzf-pool-tabix.speedup.range--> on a big multi-sample
VCF**. The slice is 213 MB of 1000 Genomes over `chr1`.

- **The August figures were 1.34-1.46x.** Since then tabix 3.11.0 parses a
  pooled chunk in segments, which drops a serial copy of the whole chunk, and the
  numbers now come from a desktop, so the rise mixes the two.
- **The `cached` column measures the halves apart.** It runs the same views
  again from the decompressed chunk cache, which inflates nothing. The line scan
  is 19-31%<!--m:bgzf-pool-tabix.scanShare.range--> of the cold query, and the
  pool reaches the rest at 2.06-2.94x<!--m:bgzf-pool-tabix.inflateSpeedup.range-->.
- **The scan is the ceiling.** It is byte scanning on enormous per-sample lines,
  so getting much past 2x on multi-sample VCF means making the scan faster.

## Verifying the pool engages

The failure mode is silence. jbrowse-web runs adapters inside a web worker, so
the pool is a worker spawning workers. Where nested workers are unavailable
(Safari before 16.4), `workersAvailable()` is false, every read inflates in
process, and nothing fails. To re-check, count `blob:` worker targets with
puppeteer (`browser.on('targetcreated', ...)`) on a session with one
bgzip-backed track plus a non-bgzip control; zero `blob:` workers on volvox is
the pool working.

## Benchmark traps

[BENCHMARKING.md](BENCHMARKING.md) holds the general rules. The ones specific to
this pool:

- **Six rounds minimum.** The HTTP cache warms for several rounds; a min over
  the unplateaued series read the pool as a 0.74x slowdown.
- **Node cannot measure it, and this doc owns that trap.** `getSharedWorkerPool()`
  needs a global `Worker` plus Blob URLs, so it resolves to `undefined`, the
  in-process path runs and every node bench reports parity. The same holds for
  any worker-shaped question. `packages/core/src/util/bgzfWorkerPool.test.ts`
  pins the property.
