# Interaction perf: which components re-render per frame

Interaction is main-thread-JS bound, not GPU- or MobX-bound. The cost is React
re-render plus the MUI/Emotion styling each render pays, so the one lever is
**fewer components re-rendering per frame**. The tax scales per track, since each
track mounts its own overlay and chrome subtree (`jb2bench/scripts/render/multibam.ts`
sweeps track count).

**The alignments display overlays are zoom-invariant — do not chase them.**
`hoverInk`, `renderSections`, `sections` and `laidOutByGroup` read no
`offsetPx`/`bpPerPx`, and `VisibleLabelsOverlay` is a canvas.

Read the trade, not the total: structural churn is the expensive class, and the

`website/scripts/measure-zoom-churn.ts` reproduces it against

same fix. **The rule is narrower than "pool every list"**: a zoom does not change
a feature's id, so `FloatingLabelsLayer` already pools, and positional keys there
would repaint every surviving label.

## An array-rebuilding computed re-renders every observer that reads it

- **A computed that rebuilds a fresh empty array is not free.** Return one shared
  frozen array (so MobX's `===` stops) and `null` from the component. A census arm
  starting at offset 0 never sees this; the mid-contig arm exists for it.
- **Clamp inside the computed.** `visibleRegions` rebuilds fresh objects every
  frame; the view's `contentRightEdgePx` applies `Math.min(trackWidthPx, …)` where
  MobX can stop at it. Publishing the raw edge changes nothing.
- **Split a computed by the clock each half answers to.** `sashimiJunctionSections`
  is the memoized merge and `projectSashimiArcs` the per-frame half:

The table is not a whole-app RNA-seq frame budget. Sashimi stays SVG: paths are

**Do the wrapper arithmetic before optimizing one.** `observer` wraps
`React.memo` and a fresh `children` defeats it, so `ZoomTransform`'s count equals
the sum of its parents' (`PaddingBlocks` + `Gridlines`).
`ZoomRenderCensus.test.tsx` asserts that equality.

## Count the renders in jsdom before you profile a build

`mobx-react-lite` names each component's reaction `observer<ComponentName>`, so
`mobx.spy()` filtered to `reaction` events **is** the per-component render count.
`products/jbrowse-web/src/tests/renderCensus.ts` is the helper;
`ZoomRenderCensus.test.tsx` drives a `zoomTo` ramp over a real session
(`ZOOM_CENSUS=1` prints per-component tables). Two limits:

- **A count is a floor.** A child re-rendered by a parent's fresh props runs no
  reaction of its own, and `mobx` emits spy events only in its development build.
- **Only the view-geometry half is deterministic.** Ruler, scalebar and overlay
  counts repeat to the integer; anything downstream of a fetch races the wall
  clock. Quote per-component counts of the first group, not the gesture total.

`products/jbrowse-web/browser-tests/probe-zoom-churn.ts` is the browser
counterpart, attributing each DOM mutation to its nearest `data-testid`; it
cannot see divs under `tracksContainer`.

## Profile the production build

Take render **counts** from a dev build and nothing else: React's dev
instrumentation inflates component cost unevenly and reorders the ranking.
`products/jbrowse-web/browser-tests/profile-zoom.ts` is the harness. Traps that
each produced a confident wrong answer:

- **Charging a message its enclosing task overstates it.** Sum the event's own
  `dur`, not its `RunTask`'s.
- **`page.mouse.wheel` measures the wrong thing.** Each call is a CDP round trip
  the page's busyness delays, so a slower build runs a shorter gesture. Drive
  wheels from inside the page on a wall-clock schedule and bound the sweep by
  `bpPerPx`; two arms over different `bpPerPx` ranges are not comparable.
- **Do not profile headless.** It falls back to Canvas2D, and bar-by-bar wiggle
  drawing swamps the trace.
- **The top-self list is truncated**, so a self-time read from it is a floor.
  `topSelf` (v8 samples) and `styleRecalc` (Blink trace events) are independent
  instruments; never add one to the other.

### Any canvas text op flushes the document's style

Setting `ctx.font` **or** calling `ctx.fillText` resolves the canvas element's
computed font, which flushes the whole document's pending style recalc;
`fillRect` does not. **An overlay that draws text must gate the text work on
something actually being drawn** — caching `ctx.font` does not help, since
`fillText` pays the same flush. Quote the `bpPerPx` range with the number.

## A loaded box owns the magnitude, the code owns the period

A pan's p99 is periodic: over-budget frames land on the coarse-block update
(`coarseDynamicBlocks`), which invalidates `coverageStats` -> `coverageDomain` ->
`renderState` and repaints every open track's canvas on one frame.

- **Test the period on frame index**, or on wall time with the stalls removed;
  a spike longer than the period displaces every later frame.
- **The spike's size is the machine.** On a loaded box the profile reads mostly
  `(program)` with every worker idle, and attribution is worthless.
- **The per-tick recompute is warranted.** `coarsetick.probe.ts` found the stats
  change for every display at every tick, so a value-equality memo on
  `coverageStats` has no case to fire in; declined.

## The model's work per step is a gate, not a probe

`workCensus` (`packages/display-test-utils/src/workCensus.ts`) counts what the
models do: each row display's `workCensus.test.ts` and the session's
`trackWorkCensus.test.ts` snapshot integer counts per step on a fake clock. It
cannot see cost inside one run, React renders, uploads, draws or milliseconds;
the render census and `probe-zoom-churn.ts` cover those.

## A stalled main thread scrolls the page in Firefox, never in Chrome

With a non-passive wheel listener that always calls `preventDefault`, Chrome
waits for the handler however long the stall lasts. Firefox gives up after
`apz.content_response_timeout` (400ms) and scrolls the page for the rest of that
wheel transaction, so a long task during a scroll-zoom is a page scroll for a
Firefox user. No automated run here shows it: puppeteer's Firefox profile raises
the pref and its wheel actions bypass APZ. The wheel controller's eased zoom
backlog (`packages/core/src/util/wheelZoom.ts`) makes how far a wheel zooms
independent of frame timing.
