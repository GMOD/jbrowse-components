# v5.0.0 release review

This file reviews the three v5 release documents — the announcement
(`v5.0.0.md`), the changelog (`v5.0.0.changelog.md`) and the plugin upgrade
guide (`website/docs/developer_guides/upgrading_v5.md`) — against main at
`a1c56db573` (2026-09-27), along with the release pipeline around them.
`pnpm release` refuses to run while this file exists: work each finding into the
drafts, then delete it.

The changelog's `changelog-through` marker names `d34adc4178` (2026-09-15).
3,374 commits landed after it, 1,813 of them touching source; every one of those
subjects was read for what the notes lack, and every claim in the three
documents was checked against the code for what they get wrong. Line numbers
below are the documents' own at `a1c56db573`.

## Direction

The notes describe the code of mid-September. The work since then changed the
config API itself: one colour object per channel, `scales.y` with
`domainQuantile` in place of `autoscale`, `rows`/`facet`/`domain` for every
stacking display, Vega-Lite's mark names, and `filter` in place of
`jexlFilters`. It also merged or retired displays: one quantitative display, one
multi-sample variant display, GC content as a wiggle track, Manhattan as the
mark display, and the arc plugin replaced by the `link` mark. The one-spelling
rulings were still landing on 2026-09-27 (`filter`, `encoding.size`, the `line`
mark), so patching bullets now means patching them again after each ruling.

**Freeze the config API, rewrite the notes once against the frozen tree, then
cut the release candidate.** The sections below are the inputs to that rewrite.

## Release blockers outside the notes

- **No Windows build ships today.** The beta.9 release run (35728634413) failed
  its Windows job at the SignPath step with "Input required and not supplied:
  organization-id", and `release.yml` has no unsigned path, so the
  artifact-verify job fails after it. The ssl.com licence is gone and the
  SignPath Foundation application may not clear before the release.
- **An unsigned v5 would lock its own updates.** v4.3.0's `app-update.yml`
  carries no `publisherName`, so a v4 install accepts any installer and v4 → v5
  updates work signed or not. v5 writes `WINDOWS_PUBLISHER_NAMES` into it, so an
  unsigned v5.0.0 carrying that list rejects every later unsigned update. The
  fix: when SignPath is unconfigured, ship the unsigned exe and installer, write
  no publisher list, and let `verifyWindows.ts` accept unsigned output. The list
  then ships with the first signed release, under whichever signer lands —
  Berkeley's InCommon certificate, Azure Artifact Signing or SignPath. The
  download page and `code-signing-policy.md` say SignPath signs the build, which
  would be false until then.
- **main's CI is red.** Eight of the last ten Push runs failed, the one on
  origin/main's tip (`2fc751f197`) among them. At `5819684155` the typecheck and
  six suites failed (`markDisplays.test.ts`, `moduleClosure.test.ts`,
  `ConfigSlotDefaults.test.ts`, `jbrowseModel.test.ts`,
  `ExportSvgDisplayTypes.test.tsx`, `ReversedRegionLabels.test.tsx`).
- **Two v4.3.0 share-link states lost their lift**, against ADR-070 and ADR-168:
  - v4.3.0 wrote the view's `highlightsVisible: false` and
    `labelsVisible: false` into a snapshot when dismissed
    (`v4.3.0:plugins/linear-genome-view/src/LinearGenomeView/model.ts:1986`).
    HEAD's `passThrough` (`launchKeys.ts:31`) holds neither, so such a link
    raises "LinearGenomeView ignored unknown key(s)". grid-bookmark's
    `bookmarkHighlightsVisible` has the same fate.
  - v4.3.0 Hi-C display state held `useLogScale` and `colorScheme`
    (`v4.3.0:plugins/hic/src/LinearHicDisplay/model.ts:58,62`); nothing on HEAD
    lifts them.
- **The release candidate has no date.** `agent-docs/TODO.md` lists nothing but
  "the release candidate's two weeks in real use, which goes here the moment a
  date exists", and `handoffs/capture-before-beta-10.md` is waiting on beta.10
  (beta.9's `@jbrowse/capture` still defaults to `jb2/latest/`, which is 4.3.0).
- **Downstream checks for the candidate window:** rebuild the store plugins in
  `~/src/jb2plugins` against it and run their `host-compat` probes; re-sync
  jb2hubs, which still writes `jexlFilters` and `multixyplot`; JBrowseR and
  jbrowse-anywidget import capture from sibling checkouts with unpushed commits.
- **After the release**, `npm deprecate @jbrowse/plugin-arc`, pointing at the
  mark display's `link` mark.
- **The staleness warning goes unread.** `check-release-drafts` warns once the
  changelog is 100 commits behind its marker, and it is 3,374 behind. A
  `pnpm release` that refused past some bound would have caught it.

## Decisions open

- The freeze date and the release candidate's two-week window.
- Windows: ship unsigned with no publisher list, or hold the Windows build.
- Whether to build the three share-link lifts above.

## The announcement

1. **Lines 19-20 and 197-203 promise configs keep working.** "your config.json
   files and sessions should continue to work as before" and "the old configs
   will migrate automatically" are false for config files: v4 wiggle
   `scaleType`, `minScore`, `maxScore`, `autoscale`, `numStdDev` and
   `numQuantile`, `posColor`/`negColor`/`useBicolor`/`densityColorRamp`, and
   Hi-C `colorScheme`/`useLogScale` are dropped without a word, so a pinned axis
   reopens autoscaled. A v4 session does lift the wiggle ones
   (`plugins/wiggle/src/LinearWiggleDisplay/retired.ts`). Say instead that v4
   sessions and share links carry over, and that a config file should go through
   `jbrowse validate`, which names what it drops.
2. **Lines 112-113, the Plot field dialog.** `883953cb44` deleted it; the menu
   row is **Edit plot...** (`markMenus.ts:72`), with **Edit as JSON...** beside
   it.
3. **Lines 98-99, "a local-percentile autoscale is the new default".** ADR-179
   (`700f3cdadf`) replaced `autoscale` with `scales.y.domainQuantile`, 0.99 on
   wiggle, toggled by **Clip outliers**. The behaviour holds and the name is
   gone.
4. **Lines 207-210 say What was removed lists the user-visible removals.** None
   of the three documents mentions the arc plugin, which `c860b6e68f` deleted
   with `LinearArcDisplay`, `LinearPairedArcDisplay` and the `logThickness` and
   `defaultPairedArcColor` jexl functions (ADR-163). An arc is a `link` mark on
   the mark display now.
5. **Lines 40-41, "every tutorial has … videos".** 28 of the 64 tutorial pages
   embed a `<Video>`; five the announcement links (cancer_sv, alu_age,
   read_marks, dtu, scrna_pseudobulk) do not. Say every screenshot is generated
   and many tutorials carry generated videos.
6. **Line 193, the insert-size caption,** describes the two-axis display that
   ADR-141 deleted. The figure is two stacked mark displays: depth as bars
   above, insert size as points below, coloured by mapping quality.
7. **Line 191, the ChromHMM caption,** says the rows are ordered by similarity
   under a dendrogram. The `chromhmm` spec facets by tissue group in Roadmap's
   order and runs no clustering.
8. **Line 50, the TP53 alt text,** names ClinVar variants; the
   `protein/connected` spec opens only the RefSeq track.
9. **Lines 107-109, the grammar paragraph.** "names a shape" steers a reader to
   a retired key (`42424b6fac`: the kind is `mark`, and `shape` is the point
   symbol), and the `stack` step is `pileup` (`d5acf9f238`). The display also
   attaches to quantitative tracks. Name the marks: bar, point, line, rule,
   span, text and link.

## The upgrade guide

1. **Lines 95-105, "Every `@jbrowse` package is served to plugins".** False
   since `4f1f0b9749` (09-17): the host serves `@jbrowse/core`, display-kit,
   display-ui and render-core, and a plugin bundles anything else, core plugins
   included. The section's own `@jbrowse/plugin-linear-genome-view` example is
   one a plugin now has to bundle, and "240 subpaths" is 259. Line 283 already
   says a runtime plugin gets no other plugin's code.
2. **Lines 7-11, 20-21 and 485-487, "migrate automatically".** The guide's later
   sections list v4 state that does not migrate, and it misses two more: the arc
   displays and `cjsUrl` plugin entries. Open with "Most v4 sessions and configs
   load, and `jbrowse validate` names the keys that no longer do."
3. **Lines 498-502 and 425-428 say the value scale and the wiggle colour never
   migrate.** In a config file that is right. In a v4 session, `retired.ts`
   lifts `scale`, `autoscale` (0.99 for `localpercentile`, 1 otherwise) and the
   min/max into `scales.y`, and `posColor`/`negColor` into the threshold `color`
   object — as lines 362-364 of the same guide say.
4. **Lines 321-327, "Display types collapsed",** names only the alignments
   displays. It also needs `LinearFeatureDisplay` → `LinearBasicDisplay`,
   `MultiLinearVariantDisplay` and `LinearVariantMatrixDisplay` →
   `LinearMultiSampleVariantDisplay`, the two GC content displays →
   `LinearWiggleDisplay` (ADR-176), and `LDDisplay` and both arc displays
   removed. A plugin matching on an old name silently stops applying. Make it a
   table, and point at `retiredTypes` for a plugin retiring its own display.
5. **Lines 66-93, "Seven went in v5".** At least eight more v4.3.0 RPC methods
   are gone: `CoreGetFeatureDensityStats`, `CoreGetFeatureDetails`,
   `ComparativeRender`, `MultiVariantClusterGenotypeMatrix` (now
   `MultiSampleVariantClusterGenotypeMatrix`),
   `MultiVariantGetSimplifiedFeatures`, `PileupGetVisibleModifications`,
   `RenderLinearReadArcsDisplay` and `RenderLinearReadCloudDisplay`.
   `RenderWiggleData` never shipped in 4.3.0. Drop the count.
6. **Lines 17-18 name the wrong package.** The embedded packages are
   `@jbrowse/react-linear-genome-view2`, `-circular-genome-view2` and
   `react-app2`, as lines 508 and 618 say.
7. **Omitted: the arc plugin.** Add it under "Removals with no replacement",
   with the `link` mark as the route.
8. **Omitted: the CJS plugin format.** `b8fafaaaa0` removed `cjsUrl`; a config
   naming one fails that plugin by name. Point at `umdUrl` or `esmUrl`.
9. **Omitted: `createViewState` is async in the circular product,** and the
   linear and app products add `createViewStateAsync` (changelog 1487-1489
   records it).
10. **Omitted: `textSearchAdapterId` is gone** (`fbda0abac2`).
11. **Lines 34-41, the highlight keys.** A v4 key the view no longer declares is
    reported as unknown, not dropped quietly, and no item is called "Toggle
    highlights"; the control is **Show highlights** under the view menu's
    Highlights submenu. Either fix the text or add the lift above.
12. **Lines 184-193** say Reactome still breaks on the `@material-ui` aliases;
    `1a5e37b13a` rebuilt it, and the generated table lists only Apollo and
    Ideogram.
13. **Lines 489-496** list Manhattan beside the mark display (it is the mark
    display, ADR-178), map only the beta-only `localpercentile`, and omit v4's
    `global`, `globalsd` and `zscore` and the removed `inverted` slot.
14. **Lines 315-319** count fifteen pinned session members and cite
    `getReferring`; `pluginFacingSessionApi.test.ts` pins eighteen, calls two,
    and names no `getReferring`.
15. **Line 97** says the hand list named 25 core subpaths; v4.3.0's named 27.
16. **Lines 480-483,** "the lint rule names it": the rule lives in this repo's
    eslint config, and the plugin template does not ship it.

## What was removed: missing entries

The list at changelog 1856-1925 also needs `@jbrowse/plugin-arc`; the `cjsUrl`
plugin format; bookmarks in browser storage and v4's `sharedBookmarks`; hiding
highlight chips; the `autoscale` slot as a whole; the LD triangle toggle;
`sv_multihop.py`; in-app derivative-allele reconstruction; and the renames by
which `LinearFeatureDisplay`, the two v4 multi-variant displays and the GC
content displays now load as their successors. Build the list and the guide's
retired-types table from a diff of the display types, slots and RPC methods
v4.3.0 registered against HEAD's, rather than by hand: the hand lists missed all
of the above.
