Hello all! I am pleased to announce JBrowse 2 v5.0.0, six months in the making —
the GPU rewrite. It replaced almost the whole app: nine of every ten lines that
ship today were written since February.

## Highlights

- **The GPU rewrite** we completely rewrote our entire rendering system to use
  GPU rendering, so you now have smooth scroll zooming and much faster
  responsiveness. The
  [optimization guide](https://jbrowse.org/jb2/docs/developer_guides/optimizations)
  covers the rest of the performance work.
- **Tutorials!** as a part of this gigantic revamp, we created a huge variety of
  tutorials demonstrating how to load data and use JBrowse 2 for a variety of
  different analysis tasks.
- **[Alignments](https://jbrowse.org/jb2/docs/user_guides/alignments_track)**
  got a simpler track menu, better color legends, and better display of
  structural variant signals like split reads. See the
  [1000 Genomes SV tutorial](https://jbrowse.org/jb2/docs/tutorials/sv_multisamples).
- **Synteny** gained a coarse zoom tier in `make-pif`, automatic filtering of
  small alignments, view-follow, and multi-genome comparisons from all-vs-all
  PAF or jcvi `.blocks` files.
- **[MAF](https://jbrowse.org/jb2/docs/user_guides/maf_track) is built in**,
  with per-row percent identity, a codon view, and a summary tier that draws a
  whole chromosome of a 464-haplotype pangenome alignment. Pangenome graphs,
  paths, and snarl VCFs read as ordinary tracks.
- **[Multi-sample variants](https://jbrowse.org/jb2/docs/user_guides/multivariant_track)**
  color by predicted consequence, SV type, or copy-number state, group rows by
  sample metadata, and render phased data as haplotypes.
- **New [`GWAS` plugin](https://jbrowse.org/jb2/docs/user_guides/gwas_track)**
  draws LocusZoom-style Manhattan plots from summary statistics, colored by LD
  read from PLINK `.ld` files, with a genotype panel below. See the
  [LD tutorial](https://jbrowse.org/jb2/docs/tutorials/ld_mosquitoes).
- **New
  [Multi-row feature tracks](https://jbrowse.org/jb2/docs/user_guides/multirow_feature_track)**
  put hundreds of rows in one track — chromosome painting, local ancestry,
  ChromHMM states — with clustering and a categorical legend.
- **New [Gene track](https://jbrowse.org/jb2/docs/user_guides/gene_track)
  features** automatically collapses a gene to one representative transcript
  when zoomed out instead of stacking every isoform. Also a variety of other
  goodies including the support of alternative genetic codes and translation
  exceptions selenoproteins and mitochondrial translations come out right.
- **[Track settings](https://jbrowse.org/jb2/docs/tutorials/display_settings)**
  can be pinned as
  [session-wide defaults](https://jbrowse.org/jb2/docs/user_guides/display_defaults)
  — one click changes the compactness of every open alignments track.
- **[Embedded components](https://jbrowse.org/jb2/docs/embedded_components)**
  have a new prop-driven interface that is much easier to use. We also refreshed
  our pythoin and R notebook style integrations, which are users of these
  embedded components.
- **New JBrowse CLI `jbrowse validate` command** checks a config before you ship
  it!

## Docs

We rebuilt the documentation site and added a lot of
[new tutorials](https://jbrowse.org/jb2/docs/tutorials) on real published data —
cancer SVs, pangenome graphs, ChromHMM, TCGA cohorts, single-cell pseudobulk,
QTL mapping — plus a [config cookbook](https://jbrowse.org/jb2/docs/cookbook)
and new [developer guides](https://jbrowse.org/jb2/docs/developer_guide). A
script captures every screenshot in the docs, so they never go stale, and each
one carries the steps that produced it — look for "Make this view yourself".

## Breaking changes

Sessions and configs from v4 migrate automatically, so most users need to do
nothing beyond taking the new version.

For users that have developed custom plugins, there are some breaking changes.
Significantly, we removed the entire concept of a "renderer" from our codebase
(which was our term for rendering static tiles on the web worker). Please see
the
[v5 upgrade guide](https://jbrowse.org/jb2/docs/developer_guides/upgrading_v5)
lists that migration and the smaller ones and contact us if you need any
assistance.

If you hit any issues or need help migrating your plugins and configs, open an
issue on [GitHub](https://github.com/GMOD/jbrowse-components/issues) or write to
jbrowse2@berkeley.edu.

Thanks to everyone, and happy browsing!
