Hello all! I am pleased to announce JBrowse 2 v5.0.0, over 7 months in the
making — the GPU rewrite.

## Highlights

Rather than list everything, here is what we think is worth a look, each linking
to the docs that cover it:

- **The GPU rewrite** replaced every line of rendering code in the app, and made
  it faster.
- **[Alignments](https://jbrowse.org/jb2/docs/user_guides/alignments_track)**
  got a simpler track menu, better color legends, and better display of
  structural variant signals like split reads, even for short paired-end reads.
  See the
  [1000 Genomes SV tutorial](https://jbrowse.org/jb2/docs/tutorials/sv_multisamples).
- **[Multi-sample variants](https://jbrowse.org/jb2/docs/user_guides/multivariant_track)**
  color by predicted consequence, SV type, or copy-number state, group rows by
  sample metadata, filter on missingness, and render phased data as haplotypes.
- **The new
  [`gwas` plugin](https://jbrowse.org/jb2/docs/user_guides/gwas_track)** draws
  LocusZoom-style Manhattan plots with LD coloring from summary statistics, plus
  a genotype panel. LD comes from PLINK `.ld` files — see the
  [LD tutorial](https://jbrowse.org/jb2/docs/tutorials/ld_mosquitoes).
- **Synteny** gained a level-of-detail tier in `make-pif`, automatic filtering
  of small alignments, view-follow, and multi-genome comparisons from all-vs-all
  PAF or jcvi `.blocks` files.
- **[MAF](https://jbrowse.org/jb2/docs/user_guides/maf_track) is built in**,
  with per-row percent identity, a codon view, and a summary tier that draws a
  whole chromosome of a 464-haplotype pangenome alignment. Pangenome graphs,
  paths, and snarl VCFs read as ordinary tracks.
- **[Multi-row feature tracks](https://jbrowse.org/jb2/docs/user_guides/multirow_feature_track)**
  put hundreds of rows in one track for chromosome painting, local ancestry, and
  ChromHMM states, with clustering and a categorical legend.
- **[Gene tracks](https://jbrowse.org/jb2/docs/user_guides/gene_track)** render
  alternative genetic codes and honor NCBI `transl_except` GFF fields, so
  selenoproteins and mitochondrial translations come out right.
  genomes.jbrowse.org already uses this for every genome with NCBI metadata.
  Zoomed out, a gene now collapses to one representative transcript — MANE
  Select, RefSeq Select, or the longest coding sequence — instead of a stack of
  overlapping isoforms.
- **[Track settings](https://jbrowse.org/jb2/docs/tutorials/display_settings)**
  can be pinned as
  [session-wide defaults](https://jbrowse.org/jb2/docs/user_guides/display_defaults),
  so one click changes the compactness of every open alignments track.
- **[Embedded components](https://jbrowse.org/jb2/docs/embedded_components)**
  are prop-driven now, configured with a declarative `init` instead of a
  hand-built MST model, and `localFiles` covers the genome as well as the
  tracks.
- **`jbrowse validate`** is a new CLI command that checks your configs.

## Docs

We rebuilt the documentation site and added a lot of
[new tutorials](https://jbrowse.org/jb2/docs/tutorials) on real published data —
cancer SVs, pangenome graphs, ChromHMM, TCGA cohorts, single-cell pseudobulk,
QTL mapping — plus a [config cookbook](https://jbrowse.org/jb2/docs/cookbook)
and new [developer guides](https://jbrowse.org/jb2/docs/developer_guide).

Puppeteer now captures every screenshot in the docs, so they never go stale, and
each one carries the steps that produced it — look for "Make this view
yourself".

## Breaking changes

Sessions and configs from v4 migrate automatically, so most users need to do
nothing beyond taking the new version.

Custom plugins are another matter. We removed the entire concept of a
"renderer", our term for rendering static tiles on the web worker. Ripping the
bandaid off was the kinder option — maintaining it would have hurt for years.
The
[v5 upgrade guide](https://jbrowse.org/jb2/docs/developer_guides/upgrading_v5)
lists the smaller migrations.

If you hit any issues or need help migrating your plugins and configs, open an
issue on [GitHub](https://github.com/GMOD/jbrowse-components/issues) or write to
jbrowse2@berkeley.edu.

Thanks to everyone, and happy browsing!
