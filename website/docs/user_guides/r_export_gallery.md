Every figure on this page is output from the
**[Export R script](/docs/user_guides/r_export)** feature: the generated `.R`
file, run through `Rscript`, unmodified. Each one re-exports a view shown
elsewhere in these docs, so you can compare the ggplot2 rendering against
JBrowse's own.

Nothing here is hand-drawn or touched up. The figures are regenerated by the
same pipeline that produces the site's screenshots, so a change to the code
generator moves the picture.

## Quantitative

A multi-wiggle track reads every BigWig into one long data.frame. The multi-row
XY and line modes facet one panel per source; density instead stacks the sources
on one continuous axis, so a cohort of hundreds compresses and overplots the way
the browser's fit-to-height display does. A single BigWig draws one panel, as
`geom_rect` bars, a line, or a viridis density strip depending on the display's
plot type.

Each panel takes its height from the display it came from — a feature track from
the rows it actually packs, a multi-wiggle from the track height the browser
gave it — so a figure keeps the proportions of the view it was exported from.

<Figure caption="Four BigWig sources faceted one per row, the multi-wiggle display's multi-row mode (volvox, ctgA:1-50,000)." src="/img/rexport/multiwiggle.png"/>

## Alignments

A BAM track exports as two stacked panels: a coverage histogram over a pileup
whose rows are packed by `IRanges::disjointBins`. Mismatches come from the MD
tag, so no reference file is needed.

<Figure caption="A coverage histogram above a pileup, the default alignments view (volvox, ctgA:1-8,000)." src="/img/rexport/alignments.png"/>

Each read's CIGAR is walked, so a deletion draws as a grey rect over the read
body, a spliced intron as an erased body with a thin teal connector, and an
insertion as a purple tick.

<Figure caption="Long reads across an insertion: CIGAR-aware bodies with indel marks (hg19, 1:85,618,922-85,621,742)." src="/img/rexport/long_reads.png"/>

JBrowse's localized **Sort by...** is reproduced by a `sorted_pileup_layout`
helper: reads covering the sort column are ordered by the criterion and placed
first as a block, then the rest fill in around them. The sort position is
emitted as an editable `sort_pos` variable.

<Figure caption="Sort by base at a SNP — reads carrying the alternate allele group at the top (volvox, ctgA:14,470-14,500)." src="/img/rexport/alignments_sort.png"/>

Base modifications are read from the MM/ML tags and drawn as per-base ticks over
the read body, coloured by modification and shaded by the ML probability. No
reference file is needed here either: the tags are walked against the read's own
CIGAR.

The coverage panel above the pileup counts the same calls per column and stacks
them into the depth bar, as JBrowse's coverage band does: a modification's share
of a column is the reads that called it over the reads that could have carried
it — which for a modification basecalled on one strand only, the usual nanopore
case, is the reads on that strand rather than every read showing the base. The
mismatch bars grey out while those are drawn, so the modification colours are
the only colour in the panel.

<Figure caption="5mC calls from a modBAM at the SNRPN imprinting centre, one tick per methylated CpG (HG002 ONT, hg38 chr15:24,948,000-24,962,000)." src="/img/rexport/modifications.png"/>

## Genes and features

Gene models draw with directional `geom_segment` bodies plus `geom_rect` boxes,
thin for exons and UTRs and thick for CDS, keyed off the feature type so coding
regions read like the browser glyph.

<Figure caption="A GFF3 gene track: directional bodies with thin exon and thick CDS boxes (volvox, ctgA:17,200-23,200)." src="/img/rexport/genes.png"/>

Nested features pack into rows with `gene_layout`, so a polyprotein and its
cleavage products stay readable.

<Figure caption="SARS-CoV-2 ORF1ab with its mature peptide products (NC_045512.2:266-21,555)." src="/img/rexport/genes_sarscov2.png"/>

## Variants

A VCF track reads over the tabix index and draws each record as a box, like a
feature track.

<Figure caption="A VCF track, rows packed by IRanges::disjointBins (volvox, ctgA:5,000-10,000)." src="/img/rexport/variants.png"/>

The multi-sample matrix display draws a per-sample genotype grid instead. Each
cell is classed ref / het / hom / other / no-call by dosage of the site's most
frequent ALT, samples are ordered by `hclust`, and the dendrogram is composed as
a left panel. Columns are laid out by site index, matching JBrowse's matrix
rather than genomic position.

<Figure caption="A 1094-sample genotype matrix with its clustering dendrogram (volvox 1000 Genomes simulation, ctgA:1-50,000)." src="/img/rexport/variant_matrix.png"/>

In phased mode each sample expands into its two haplotypes and cells are
coloured per allele rather than by dosage.

<Figure caption="A phased trio genotype matrix, each sample split into two haplotype rows (KHV trio, chr1:62,174,000-65,097,304)." src="/img/rexport/trio_phased.png"/>

## Structural variants

Clipped reads are drawn as coloured bars at the clip end, so a breakpoint reads
as a column of them down the pileup — soft clips from the CIGAR's `S` operations
and hard clips from `H`.

<Figure caption="Soft- and hard-clip bars stacking at one breakpoint (volvox, ctgA:2,559-2,760)." src="/img/rexport/sv_clipping.png"/>

The coverage panel above the pileup counts the same events per column and draws
them as JBrowse's interbase histogram — insertions, soft clips and hard clips
stacked into a bar hanging down from the top of the depth axis — with a triangle
over any column where they pass 30% of local depth. Both follow the track menu's
**Show interbase indicators** toggle, and the bar height is emitted as an
editable `interbase_scale` so a breakpoint over shallow coverage can be
exaggerated.

A fusion puts its two partners in one multi-region view, so the reads that cross
the junction run from the left panel into the right one on a shared axis.

<Figure caption="BCR-ABL in K562 PacBio Iso-Seq: reads spanning chr22 BCR into chr9 ABL1 on one cumulative axis." src="/img/rexport/sv_fusion.png"/>

A multi-sample SV callset draws as a genotype panel over the genes it hits, each
row a sample and each column a call, coloured by dosage of the site's most
frequent ALT.

<Figure caption="1000 Genomes SV genotypes for 3,202 samples over the gene track (hg38, chr19:42.7-47.8 Mb)." src="/img/rexport/sv_multisample.png"/>

## Hi-C

A `.hic` contact map is read with `strawr` and rotated 45° into the triangular
view — the diagonal on the genomic x-axis, interaction distance up the y-axis —
so it stacks with ordinary 1-D tracks. Bin size and normalization are emitted as
editable variables.

<Figure caption="A Hi-C contact map rotated into the triangular view, log-scaled viridis (hg19, chr8:52,000,000-56,200,000)." src="/img/rexport/hic.png"/>

## GWAS

Summary statistics from a tabix'd BED draw as a Manhattan plot of -log10(p)
against position, with the 5e-8 genome-wide significance line.

<Figure caption="GWAS summary statistics as a Manhattan plot with the significance line (hg19 chr2)." src="/img/rexport/gwas.png"/>

## Multiple regions

A discontiguous view concatenates its regions left-to-right onto one
cumulative-bp axis — the layout JBrowse uses internally — with a region ruler on
top, a divider between regions, and each region keeping its own coordinate
labels. Every panel shares the axis, so rows stay aligned across the divider.

A Hi-C panel is read pair-by-pair over the regions, so the block between two
windows is drawn as well as each window's own — the contacts across the divider
are the reason to put the two side by side.

<Figure caption="Two chr8 windows on one cumulative axis, the Hi-C panel spanning the divider: the central pyramid is the contacts between the two windows, not within either (hg19)." src="/img/rexport/multiregion.png"/>

This is most useful when the comparison is the point — two marker loci side by
side, with every track faceted the same way across both.

<Figure caption="Single-cell ATAC pseudobulk at CD8A and MS4A1, two regions on one axis: T-cell clusters open at the left locus, B-cell clusters at the right (10x 5k PBMC)." src="/img/rexport/scatac_multiregion.png"/>

## What the script looks like

The details are in the [Export R script guide](/docs/user_guides/r_export). In
short: one `plot_regions(regions)` function that reads each track from source
and stacks one ggplot panel per track with `patchwork`, plus every helper it
needs emitted inline as a plain, editable R function. The current view is one
call at the bottom, so looping it over a BED file batch-renders many loci.

## Reproducing these

Each figure above is one [`jb2export`](/docs/jbrowse-img) command, which builds
the same view headlessly and writes the script instead of an image (`--out`
ending in `.R` selects it). Most name their files outright, so the command says
what it reads:

```bash
jb2export --fasta <ref.fa> --loc <region> --bam <reads.bam> --out fig.R
Rscript fig.R
```

A few name a public config and pass the view as a session spec instead — the
same `{views:[…]}` JSON a `&session=spec-…` URL carries. Those are the figures
whose tracks a file flag cannot express, for instance because the adapter
carries a setting no flag has (the GWAS track's `scoreColumn`), because the
per-source names, groups and colours of a cohort track are the point of the
figure, or because the file's contig names are reconciled by the config's
aliases. Either way nothing here needs a checkout — every path is a URL.

The commands below are generated from the same specs the figure sweep runs, so
each is literally what drew the picture above it. Requires `jb2export`
(`npm install -g @jbrowse/img`), `Rscript`, and that figure's
[packages](/docs/user_guides/r_export#requirements).
