Every figure on this page is output from the **[Export R script](/docs/user_guides/r_export)**
feature: the generated `.R` file, run through `Rscript`, unmodified. Each one
re-exports a view shown elsewhere in these docs, so you can compare the ggplot2
rendering against JBrowse's own.

Nothing here is hand-drawn or touched up. The figures are regenerated by the
same pipeline that produces the site's screenshots, so a change to the code
generator moves the picture.

## Quantitative

A multi-wiggle track reads every BigWig into one long data.frame and facets by
source. A single BigWig instead draws one panel, as `geom_rect` bars, a line, or
a viridis density strip depending on the display's plot type.

<Figure caption="Four BigWig sources faceted one per row, the multi-wiggle display's multi-row mode (volvox, ctgA:1-50,000)." src="/img/rexport/multiwiggle.png"/>

## Alignments

A BAM track exports as two stacked panels: a coverage histogram over a pileup
whose rows are packed by `IRanges::disjointBins`. Mismatches come from the MD
tag, so no reference file is needed.

<Figure caption="A coverage histogram above a pileup, the default alignments view (volvox, ctgA:1-8,000)." src="/img/rexport/alignments.png"/>

Each read's CIGAR is walked, so a deletion draws as a grey rect over the read
body, a spliced intron as an erased body with a thin teal connector, and an
insertion as a purple tick.

<Figure caption="Long reads across an insertion: CIGAR-aware bodies with indel marks (hg19, 1:85,618,922-85,621,742)." src="/img/rexport/long_reads.png"/>

JBrowse's localized **Sort by...** is reproduced by a `sorted_pileup_layout`
helper: reads covering the sort column are ordered by the criterion and placed
first as a block, then the rest fill in around them. The sort position is
emitted as an editable `sort_pos` variable.

<Figure caption="Sort by base at a SNP — reads carrying the alternate allele group at the top (volvox, ctgA:14,470-14,500)." src="/img/rexport/alignments_sort.png"/>

## Genes and features

Gene models draw with directional `geom_segment` bodies plus `geom_rect` boxes,
thin for exons and UTRs and thick for CDS, keyed off the feature type so coding
regions read like the browser glyph.

<Figure caption="A GFF3 gene track: directional bodies with thin exon and thick CDS boxes (volvox, ctgA:17,200-23,200)." src="/img/rexport/genes.png"/>

Nested features pack into rows with `gene_layout`, so a polyprotein and its
cleavage products stay readable.

<Figure caption="SARS-CoV-2 ORF1ab with its mature peptide products (NC_045512.2:266-21,555)." src="/img/rexport/genes_sarscov2.png"/>

## Variants

A VCF track reads over the tabix index and draws each record as a box, like a
feature track.

<Figure caption="A VCF track, rows packed by IRanges::disjointBins (volvox, ctgA:5,000-10,000)." src="/img/rexport/variants.png"/>

The multi-sample matrix display draws a per-sample genotype grid instead. Each
cell is classed ref / het / hom / other / no-call by dosage of the site's most
frequent ALT, samples are ordered by `hclust`, and the dendrogram is composed as
a left panel. Columns are laid out by site index, matching JBrowse's matrix
rather than genomic position.

<Figure caption="A 1094-sample genotype matrix with its clustering dendrogram (volvox 1000 Genomes simulation, ctgA:1-50,000)." src="/img/rexport/variant_matrix.png"/>

In phased mode each sample expands into its two haplotypes and cells are
coloured per allele rather than by dosage.

<Figure caption="A phased trio genotype matrix, each sample split into two haplotype rows (KHV trio, chr1:62,174,000-65,097,304)." src="/img/rexport/trio_phased.png"/>

## Hi-C

A `.hic` contact map is read with `strawr` and rotated 45° into the triangular
view — the diagonal on the genomic x-axis, interaction distance up the y-axis —
so it stacks with ordinary 1-D tracks. Bin size and normalization are emitted as
editable variables.

<Figure caption="A Hi-C contact map rotated into the triangular view, log-scaled viridis (hg19, chr8:52,000,000-56,200,000)." src="/img/rexport/hic.png"/>

## GWAS

Summary statistics from a tabix'd BED draw as a Manhattan plot of -log10(p)
against position, with the 5e-8 genome-wide significance line.

<Figure caption="GWAS summary statistics as a Manhattan plot with the significance line (hg19 chr2)." src="/img/rexport/gwas.png"/>

## Multiple regions

A discontiguous view concatenates its regions left-to-right onto one
cumulative-bp axis — the layout JBrowse uses internally — with a region ruler on
top, a divider between regions, and each region keeping its own coordinate
labels. Every panel shares the axis, so rows stay aligned across the divider.

<Figure caption="Two regions on one cumulative axis, each keeping its own genomic tick labels (hg19, chr8 in two windows)." src="/img/rexport/multiregion.png"/>

This is most useful when the comparison is the point — two marker loci side by
side, with every track faceted the same way across both.

<Figure caption="Single-cell ATAC pseudobulk at CD8A and MS4A1, two regions on one axis: T-cell clusters open at the left locus, B-cell clusters at the right (10x 5k PBMC)." src="/img/rexport/scatac_multiregion.png"/>

## Reproducing these

Each figure is one `jb2export` command — the [CLI](/docs/cli) builds the same
view headlessly and writes the script instead of an image:

```bash
jb2export --fasta ref.fa --bigwig signal.bw --loc chr1:1-50000 --out fig.R
Rscript fig.R
```

`--out` ending in `.R` selects the script; any other extension renders an image
as usual. It works for the linear genome view only — the dotplot, synteny and
circular views have no R export.

## What the script looks like

The details are in the [Export R script guide](/docs/user_guides/r_export). In
short: one `plot_regions(regions)` function that reads each track from source
and stacks one ggplot panel per track with `patchwork`, plus every helper it
needs emitted inline as a plain, editable R function. The current view is one
call at the bottom, so looping it over a BED file batch-renders many loci.
